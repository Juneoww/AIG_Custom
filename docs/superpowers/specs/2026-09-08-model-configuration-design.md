# 模型配置改造设计草案

状态：用户已确认，进入实现。分支 codex/model-configuration，基于 develop 8aa306c56。

## 已明确的需求

1. 将界面的“供应商模型”统一改为“模型ID”。
2. 为每个输入框提供灰色示例，帮助用户理解填写内容。
3. 增加真正验证模型可调用性的功能及按钮。

## 表单设计

保留现有新增、编辑表单布局及角色决定的全局/私有范围。模型列表列名也改为“模型ID”；接口字段 provider_model 和数据库字段保持兼容。

| 输入框 | 空白时的灰色示例 |
| --- | --- |
| 模型名称 | 例如：内网安全分析模型 |
| 模型ID | 例如：internal-chat |
| 基础 URL | 例如：http://inference.internal:8000/v1 |
| 访问 Token | 输入模型服务的 API Key |
| 调用限制 | 例如：5 |
| 备注 | 例如：用于内网安全扫描分析 |

示例只作为 placeholder，不作为实际值提交。编辑时显示已有非敏感值；Token 继续不回填，并提示留空保留。新建时调用限制允许空白，说明空白使用当前默认值 0；已有配置保留原值。沿用组件的灰色 placeholder 样式，不引入新主题或重排页面。

## 连通性测试方案

推荐在新增和编辑表单的保存按钮旁增加“测试连通性”。使用当前表单中的模型ID、基础 URL、Token，未保存也可以测试；模型名称、备注、调用限制不作为测试前置条件。

其他方案：只测试已保存配置需要先保存错误数据；保存时自动测试会让保存依赖外部服务，并触发用户未主动选择的模型调用。本次采用手动测试，测试和保存独立。

- 点击后显示“测试中…”，阻止重复测试，暂时禁用提交和影响请求的字段；离开或取消表单时取消请求，忽略迟到结果。
- 成功显示“连接成功，模型可正常响应”及本次耗时；更改模型ID、URL 或 Token 后清除旧结果，避免旧成功状态被误认为适用于新配置。
- 失败显示经过分类的中文原因，包括地址/参数无效、认证失败、模型或接口不存在、请求限流、超时、网络或证书异常、返回内容不符合预期。
- 新增时需要填写 Token。编辑时 Token 留空，可以在权限校验后由服务端使用保存的 Token；如果基础 URL 改变，测试要求重新输入 Token，避免旧凭据被发送到新的地址。
- 同一约束也适用于保存：更改基础 URL 时必须提供新的有效 Token，防止先保存新地址再留空测试绕过凭据地址边界。比较规范化的完整基础 URL（保留 API 路径），仅尾斜线与默认端口等语义等价差异不视为地址变化。
- 测试不保存模型、不覆盖配置、不创建扫描任务；保存不强制要求测试成功。

## 后端与访问控制

新增受治理的模型测试 POST 接口，分别支持当前未保存输入与可编辑的已保存模型。遵循现有 Cookie 会话、首次改密、角色权限、CSRF 和审计规则；普通用户不能引用他人私有模型的 Token。只读 YAML 模型和审计员不增加测试入口。

由平台服务端发出一次兼容 Chat Completions 的简短模型请求，支持 HTTP/HTTPS 和合法内网地址；限制到 HTTP 模型调用所需的协议与地址格式，拒绝 URL 内嵌账号、不安全的特殊地址以及凭据跨地址跳转。HTTPS 校验服务器证书，30 秒超时，不自动重试，并限制响应体大小。成功需获得有效的模型文本响应，不能只根据 HTTP 200 判定。

测试响应仅包含固定结果代码、用户可读说明和耗时，不返回 Token、模型原始响应或底层错误详情；请求体和认证内容不进入日志。对测试入口增加合理的并发/频率约束。测试代表平台服务端此时可调用该模型，不承诺不同 Agent 网络环境的可达性。

## 验证与交付

- 前端：标签、所有 placeholder、新建测试、编辑留空 Token、缺参、测试中状态、重复点击、取消、字段变化清除旧结果、失败后可重试。
- 后端：成功响应、认证失败、错误模型/路径、限流、超时、异常响应、同源/重定向边界、权限与 CSRF、保存的 Token 不回传或泄漏、测试无配置写入。
- 使用隔离本地模型靶场和虚构 Token 验收，不调用用户真实模型。
- 同步中英文 API 文档与 Swagger JSON/YAML/Go 三件套，执行相关 Go、前端测试和构建，再更新本地预览。
- 不修改调用限制在各扫描引擎中的既有含义；不增加模型厂商向导、模型列表自动发现或自动选择模型。
