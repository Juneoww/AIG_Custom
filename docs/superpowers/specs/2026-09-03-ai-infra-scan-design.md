# AI 基础设施扫描专属任务台设计

**状态：** 已与用户确认，待实施  
**分支：** `codex/ai-infra-scan`（基于 `develop`）  
**日期：** 2026-09-03

## 1. 目标与范围

本次仅实现“扫描任务”二级导航中的 **AI 基础设施扫描** 专属工作流。用户从该入口进入后，应看到仅包含 `ai_infra_scan` 的任务台，并能创建、查看和管理同一类别的任务。

本次范围包括：

- 专属任务台、专属新建页和专属详情回跳；
- AI 基础设施扫描的状态筛选、运行态势与任务列表；
- 从“凭证配置 → 模型配置”选择当前可用的受治理模型；
- 目标、超时、端口扫描模式、附件及确认流程；
- 固定任务输出语言为中文，隐藏语言控件。

本次不包括：

- MCP、模型红队评测、Agent 扫描等其余三个二级入口的产品改造；
- 扫描引擎、报告映射或后端**列表**合同的改动；
- 在任务列表批量展示原始目标、端口、凭据、原始结果或风险细节；
- 修改现有“凭证配置”页面的模型管理能力。

## 2. 路由与导航

| 用户意图 | 路由 | 页面行为 |
| --- | --- | --- |
| 进入 AI 基础设施扫描 | `/tasks/ai-infra` | 固定按 `task_type=ai_infra_scan` 查询的专属任务台。 |
| 新建任务 | `/tasks/ai-infra/new` | 预设并锁定 `ai_infra_scan`，不显示任务类型选择。 |
| 查看任务详情 | `/tasks/ai-infra/:taskId` | 仅展示该类型任务；返回专属任务台。 |
| 通用任务中心 | `/tasks`、`/tasks/new`、`/tasks/:taskId` | 保持现有全类型行为，兼容既有链接。 |

二级导航中的“AI 基础设施扫描”指向 `/tasks/ai-infra`。`/tasks/ai-infra/new` 必须在动态详情路由之前注册，避免被 `:taskId` 捕获。

导航交互沿用现有分组模式并明确如下：父级“扫描任务”仍是进入通用 `/tasks` 的可点击链接，独立的展开按钮只控制子菜单；进入任意 `/tasks/**` 路由时，任务分组自动展开；用户在同一路由内手动收起后保持收起，直到发生新的任务路由跳转；侧栏折叠时不渲染二级菜单；在 AI 基础设施专属路由中，父级和“AI 基础设施扫描”子项均显示活动状态。

专属详情页收到的任务若不是 `ai_infra_scan`，不得以 AI 基础设施扫描详情展示；应给出明确但不泄露其他任务信息的错误/空状态，并保留正常的后端鉴权边界。

## 3. 专属任务台

### 3.1 数据和筛选

复用现有 `GET /api/v1/platform/tasks`，固定传入 `task_type=ai_infra_scan`。任务状态仍由服务端在分页前筛选，页面只提供“任务状态”筛选，不显示冗余的类型筛选。

不改变现有 `TaskSummary` 的安全窄合同。该合同仅包含任务 ID、负责人、任务类型、状态、创建时间和更新时间，且 API/Swagger 测试对字段集合有严格约束。因此不得为了页面密度将目标、端口、模型、参数、附件或原始结果加入列表响应，也不得对每一行发详情请求。

### 3.2 页面内容

页面内容按以下顺序组织：

1. 标题“AI 基础设施扫描”、已授权目标范围的说明和“新建 AI 基础设施扫描任务”主操作；
2. 任务状态筛选；
3. 运行态势：匹配任务、正在执行、等待调度、需关注；指标基于已加载的安全摘要派生，明确标注当前页/当前查询语义；
4. 任务表格：任务 ID、负责人、状态、创建时间、更新时间、查看；
5. 现有分页、加载、空数据、无权和错误状态。

任务类型在该专属页中是固定上下文，不作为表格列出现。目标数量、超时、端口模式和扫描模型在详情页的安全输入摘要中展示。扫描模型的持久化展示仅通过下文定义的安全 `model_id` 摘要完成，不改变任务列表合同。

审计员保持只读：可访问任务台和详情，但不显示新建任务操作。

## 4. 新建 AI 基础设施扫描任务

### 4.1 表单结构

专属新建页移除“任务类型”步骤，按以下顺序展示：

1. **扫描目标**：多行目标输入、目标表达式预览和已授权范围提示；
2. **扫描配置**：扫描模型、超时、端口扫描模式；
3. **附件**：沿用 opaque 附件上传与所有者隔离；
4. **确认**：授权确认、取消和创建操作。

目标表达式规则、65,536 上限、超时范围、端口模式警示、附件预检、幂等提交和网络确认不确定时的显式重试，均沿用现有实现。

### 4.2 扫描模型选择

“模型 ID”自由文本输入改为“扫描模型”选择器。

- 数据源为当前会话主体可见的受治理模型目录 `GET /api/v1/platform/models`；
- 选项值为 opaque 模型 ID，标签由模型名称、供应商模型和作用范围组成；绝不显示 Token 或将其写入请求；
- 仅显示当前主体可见且 `disabled=false` 的模型；平台全局模型和用户私有模型的可见性仍由服务端决定；
- YAML 只读模型可作为可选受治理模型，`read_only` 只限制编辑，不表示不能被任务引用；
- 选择器需独立处理加载、无可用模型、失败和重试状态；无可用模型时提供前往“凭证配置 → 模型配置”的入口；
- 维持“不使用模型”选项，以兼容现有 AI 基础设施扫描 API 的可选 `model_id` 语义；选中时请求中省略 `model_id`；
- 创建服务仍必须在持久化前再次解析模型 ID，处理模型被禁用、删除或权限改变的竞争情况。

若模型目录超过单页容量，选择器必须提供继续加载/搜索的可达路径，不得悄然遗漏后续页中可选的模型。

### 4.3 固定中文输出

不再向用户显示语言选择。专属页始终以 `country_iso_code: "zh_CN"` 创建任务，确保执行进度、AI 分析和相关输出使用中文。该字段不代表界面语言、扫描区域或目标位置。

### 4.4 提交与回跳

创建请求固定使用 `task_type: "ai_infra_scan"`。成功后导航至 `/tasks/ai-infra/:taskId`；取消和专属详情页的返回操作均返回 `/tasks/ai-infra`。

## 5. 专属详情

详情页复用现有短轮询、取消权限、取消状态待确认处理和报告入口。标题和返回链接采用 AI 基础设施扫描语境。

安全输入摘要展示：

- 目标表达式数量；
- 扫描模型（未选择时明确显示）；
- 超时；
- 端口扫描模式及其可信范围。

为使模型选择在刷新和深链后仍可恢复，`TaskDetail.input_summary` 新增可选的安全 `model_id`：它仅来自已持久化、已解析的任务参数，绝不包含 Token、Base URL 或嵌套凭据对象。前端以当前受治理模型目录将该 ID 映射为模型名称；若模型后来被删除、停用或不再可见，则显示“已选择的模型（ID: …）”，不伪造可用状态。

不得显示原始目标文本、附件内容、模型凭据或内部引擎输出。任务详情对非终态继续使用现有有界退避轮询；审计员不可取消。

## 6. 实现边界

建议以最小复用方式实现：

- 为 `TaskListPage` 增加可选的固定任务类型/页面上下文配置，复用分页、状态、查询和安全列表解析；
- 为 `TaskCreatePage` 增加可选的锁定任务类型和专属回跳配置，AI 基础设施专属页只渲染相关字段；
- 为 `TaskDetailPage` 增加可选的期望任务类型和返回路径配置；
- 将模型目录查询和选择逻辑封装为任务表单专用、可测试的组件/Hook，复用现有模型 API 解析器；
- 以最小 API 扩展将已解析的 `model_id` 加入 `TaskDetail.input_summary`，并同步更新 DTO 解析、中文/英文 API 参考、Swagger 三件套和对应合同测试；
- 导航元数据和路由测试集中声明新路径，避免在 Sidebar 中散落路径判断。

通用任务页面、任务列表合同和扫描引擎保持不变；仅 `TaskDetail` 的安全输入摘要新增可选 `model_id`。

## 7. 错误处理与权限

- 任务台保留加载、空列表、403 和可重试错误状态；
- 模型目录加载失败不可伪装成“没有模型”，应提供可见重试；
- 模型目录为空时，用户可不选模型继续创建；若选择器在产品实现中被设为必选，应先另行确认产品规则；
- 附件、创建和取消继续使用现有 AbortController、幂等键、互斥和显式重试语义；
- 浏览器不能提交 Token，后端仍是模型可见性、启用状态和任务权限的最终校验边界；
- `model_id` 是供详情恢复的安全 opaque 标识，不得被解释为凭据、Base URL 或当前可用性的证明；
- 不匹配的专属详情路由不能泄露其他任务的内容。

## 8. 测试与验证

前端测试至少覆盖：

- 二级导航跳转、折叠状态和专属入口激活；
- `/tasks/ai-infra` 固定发送 `task_type=ai_infra_scan`，不渲染类型筛选/列，状态筛选与分页仍正确；
- 审计员不显示新建按钮；
- 专属创建页不渲染类型或语言控件，提交载荷固定包含 `task_type: "ai_infra_scan"` 与 `country_iso_code: "zh_CN"`；
- 模型目录的加载、可选项过滤、禁用项排除、无模型、失败重试和请求中 `model_id` 省略/写入；
- `TaskDetail.input_summary.model_id` 的安全投影、前端名称映射、模型删除/不可见后的回退文案，以及不返回 Token/Base URL；
- 成功创建后跳转至专属详情，取消与返回均回到专属任务台；
- 详情页任务类型不匹配时不展示为 AI 基础设施扫描；
- 现有通用任务页的行为不回归。

验证命令以 `web/console` 的 Vitest 套件为主。因该扩展涉及 API/任务 DTO，还必须执行 `go test ./internal/apidocs`，并同步检查 `docs/api/reference.md`、`docs/api/reference.en.md`、`internal/apidocs/swagger.yaml`、`internal/apidocs/swagger.json` 和 `internal/apidocs/docs.go`。完整 Go 测试在可用 Go 环境中执行；当前环境未发现 `go` 可执行文件，因此无法在此阶段运行 `go test ./...`。
