# MCP 安全扫描工作台设计

**状态：** 已由产品确认，待进入实现规划  
**日期：** 2026-09-02  
**范围：** 企业控制台中“扫描任务”下的 MCP 安全扫描二级页面；本设计不包含代码实现。

## 1. 目标

让用户能从一个专门的工作台中发起、跟踪和复核 MCP 安全扫描，而不是先进入全量任务列表再筛选任务类型。页面应清楚区分两类已存在的扫描对象：

1. **代码 / 仓库扫描**：Git 仓库或已上传的压缩包，执行信息收集、代码审计和漏洞整理；
2. **受控运行服务扫描**：运行中的 MCP 服务，执行信息收集、恶意行为测试、漏洞验证和漏洞整理。

页面服务于“发现风险 → 查看任务状态 → 阅读报告 → 修复并复测”的闭环。

## 2. 信息架构

全局侧边栏的“扫描任务”展开为四个二级分类：

```text
扫描任务
├─ MCP 安全扫描                 ← 当前页面
├─ AI 基础设施扫描
├─ 模型红队评测
└─ Agent 工作流扫描
```

“MCP 安全扫描”进入 MCP 类型的工作台。全量扫描任务列表仍保留为跨类型查询入口；MCP 工作台只呈现 `mcp_scan` 任务和关联报告。

## 3. MCP 工作台页面

页面按从“行动”到“处置”的顺序组织：

### 3.1 页头

- 面包屑：`扫描任务 / MCP 安全扫描`；
- 标题：`MCP 安全扫描`；
- 说明：`面向 MCP 服务、工具定义与代码的专项安全评估`；
- 主操作：`新建 MCP 扫描`。安全审计员不可见该操作。

### 3.2 概览指标

使用四张紧凑指标卡呈现当前用户权限范围内的：

| 指标 | 含义 |
| --- | --- |
| 进行中 | 状态为 `dispatching` 或 `running` 的 MCP 任务数 |
| 待调度 | 状态为 `pending` 或 `dispatch_unknown` 的 MCP 任务数 |
| 高风险发现 | MCP 报告中的高风险发现数 |
| 最近完成 | 最近 30 个自然日内完成的 MCP 任务数 |

指标不显示原始任务内容、密钥、完整附件路径或未经白名单过滤的 Agent 数据。

首期不在本页提供时间范围选择器；所有指标固定使用最近 30 个自然日，避免指标与任务表口径不一致。

### 3.3 扫描对象选择

在主任务区域上方显示两个同等权重的操作卡，点击后进入预设了扫描对象模式的 MCP 创建流程：

| 卡片 | 输入来源 | 扫描阶段 | 文案重点 |
| --- | --- | --- | --- |
| 代码 / 仓库扫描 | Git 仓库或压缩包附件 | 信息收集 → 代码审计 → 漏洞整理 | MCP 服务、工具定义、代码和 Agent Skill 一致性审计 |
| 受控运行服务扫描 | 经授权的运行中 MCP 服务地址 | 信息收集 → 恶意行为测试 → 漏洞验证 → 漏洞整理 | 工具投毒、危险工具行为、权限与数据泄露风险 |

卡片必须写入并提交不可变的 `source_kind` 枚举，而不是由前端文案或后端启发式推断：

- `repository`：必须提供一个受支持的 Git 仓库引用或至少一个受支持的代码压缩包附件；
- `service`：必须提供一个 MCP 服务端点，且不得同时提交代码压缩包附件；
- 任一模式的格式、来源或附件组合冲突时，服务端在创建任务前拒绝请求；历史任务缺少该字段时，在工作台显示“历史任务 / 对象未归类”，不得反向猜测或改写其执行类型。

服务扫描在提交前必须由发起者勾选“我确认已获得该目标的安全测试授权”。服务端必须拒绝未确认的请求，并将确认值、当前主体、任务 ID 和时间写入审计记录。首期不假设平台已经具备目标地址白名单或受治理连接资产；因此页面文案将其称为“用户授权声明”，而不是平台验证过的授权。日后若引入目标范围资产，应以新的 `authorized_scope_id` 替代或补充该声明，不能复用自由文本密钥或 Header。

创建页继续使用受治理的模型 ID、并发数、输出语言和 opaque 附件 ID；浏览器不接收模型密钥或原始认证头。若后续需要连接凭据，应另行设计受治理的连接配置引用，不能在本页面新增自由文本密钥输入。

### 3.4 进行中任务

显示 MCP 类型的近期非终态任务表。服务端按更新时间倒序返回最多 10 条，列为：

- 安全任务标签（例如“`MCP 扫描 · ab12cd34`”，不回显原始目标或任务说明）；
- 扫描对象类别；
- 当前阶段；
- 状态；
- 更新时间；
- 查看详情操作。

代码扫描的阶段名称为“信息收集”“代码审计”“漏洞整理”；服务扫描为“信息收集”“恶意行为测试”“漏洞验证”“漏洞整理”。当前阶段只能消费服务端安全投影中的枚举值；没有该字段时，显示“阶段未提供”，不得以任务状态或原始日志伪造精确进度。

### 3.5 最近风险

显示 MCP 报告的安全摘要：高/中/低风险级别、固定风险类型、服务端脱敏后的简短摘要和报告入口。最近风险按严重程度（高→中→低）再按报告完成时间倒序排列，最多显示 5 条。首期风险分类包括：

- 危险工具行为；
- 命令或文件相关风险；
- 权限与越权风险；
- 敏感数据泄露；
- 工具投毒；
- Agent Skill 描述与实现不一致。

每项跳转到既有不可变报告详情。报告详情仍只消费服务端的白名单 RenderModel，不展示原始扫描结果；页面摘要最长 160 个字符，且不得包含原始请求、完整端点、内部路径、凭据、Header 或未过滤的工具调用参数。

### 3.6 历史与治理入口

页面底部提供“查看 MCP 扫描记录与报告”入口，进入已带 `task_type=mcp_scan` 的任务或报告筛选结果；另提供关联 MCP 规则/插件知识库的入口，目标为既有 `/knowledge/mcp`。该入口用于治理和复测，不创建单独的 MCP 资产台账。

## 4. 角色、安全与状态要求

- 普通用户和管理员可创建 MCP 扫描；安全审计员只读；
- 任务和报告继续遵守现有所有者隔离与管理员治理范围；
- 服务扫描必须记录用户授权声明；该声明是创建门槛与审计证据，不等同于外部资产所有权的技术验证；
- 浏览器端仅显示安全摘要；不得新增原始日志、内部 WebSocket 信息、真实文件路径、模型 Token 或自由文本认证头；
- 空、加载、无权限和请求失败必须使用不同页面状态；
- 非终态任务可短轮询，写操作失败不得自动重放；
- 窄屏下侧栏改为纵向布局，指标卡和对象卡从多列变为单列，表格保留可横向滚动的可访问语义。

## 5. 数据与实现边界

现有平台已经可承载 MCP 类型的任务创建、状态、附件、受治理模型引用、任务列表、任务详情、不可变报告评分与风险摘要。为支持本工作台，规划必须新增一个服务端只读的 MCP 工作台安全投影；可使用独立端点或受控扩展现有任务/报告接口，但不得把原始字段直接暴露给浏览器。

该投影至少包含以下白名单字段：

```text
MCPWorkbenchTask
- task_id: opaque ID
- label: 服务端生成的安全任务标签
- source_kind: repository | service | legacy_unknown
- phase: 信息收集 | 代码审计 | 恶意行为测试 | 漏洞验证 | 漏洞整理 | null
- status: 既有受治理任务状态
- updated_at: 时间戳

MCPRiskHighlight
- report_id: opaque ID
- task_id: opaque ID
- severity: high | medium | low
- category: 固定风险分类枚举
- summary: 脱敏且长度受限的摘要
- completed_at: 时间戳
```

指标、进行中任务和最近风险必须全部由此投影返回，并继续受现有任务/报告所有权与角色过滤控制。该投影不得包含任务正文、真实仓库地址、服务端点、附件名或路径、模型 ID、原始输出、工具参数、日志或原始证据。

单个 MCP 工具清单及其权限画像、单条动态测试证据、逐阶段真实完成比例和实时原始执行日志均不属于首期工作台；只有在另行定义专门的白名单数据契约后才能展示。首期不得以占位或模拟数据将上述内容表现为真实扫描结果。

## 6. 非目标

- 不实现产品代码、API、路由或数据迁移；
- 不引入自定义请求 Header、明文凭据输入或未经治理的远程连接配置；
- 不创建独立 MCP 资产管理、告警中心或规则编辑器；
- 不改变 AI 基础设施、模型红队评测或 Agent 工作流扫描的业务语义。

## 7. 验收标准

1. 用户可以从“扫描任务”的二级导航直接定位 MCP 工作台；
2. 页面能一眼区分代码/仓库扫描与受控运行服务扫描，且 `source_kind` 会被服务端持久化并参与执行校验；
3. 服务扫描在未提交用户授权声明时无法创建，确认记录可在审计中追溯；
4. MCP 任务、风险和报告与其他任务类型明确隔离展示；
5. 创建入口、附件、模型引用和结果展示不突破既有权限与敏感信息边界；
6. 工作台仅消费指定的安全投影；API 未提供的工具、证据、日志或阶段数据不会被伪造成真实数据；
7. 原型的层级与关键操作符合已确认的 MCP 安全扫描工作台视觉方向。
