# 安全报告决策中心设计说明

**日期：** 2026-08-28
**范围：** 登录后的 `/reports` 报告台账与 `/reports/:reportId` 不可变报告详情；不修改报告 API、解析器、导出协议、权限或快照内容。

## 目标

将安全报告从“能读取的归档表格”升级为面向管理者复核与处置的报告决策中心：先让人辨认当前查询范围内哪些报告需要优先复核，再进入同一份不可变快照，看到风险结论、处置建议和可追溯技术证据。

页面延续已确认的高级雾灰浅色体验和 Fluent 主题 token。它不能把分页数据伪装成全局风险态势，也不能把历史快照中的品牌、评分、结论或技术发现改写成实时事实。

## 已确认的产品取向

采用“报告决策中心”而非单纯档案库或叙事阅读器：

1. **复核优先。** 列表先说明当前服务端查询、匹配报告总数与本页可证实的风险信号，再保留可审计台账。
2. **结论优先。** 详情页把安全评分、风险分布、覆盖范围、结论和修复建议提升到技术元数据之前；技术发现仍是可追溯事实来源。
3. **快照不被重写。** 所有文字与数值来自已校验的 `ReportSummaryView` / `ReportDetailView`。PDF 导出继续下载同一快照，且保留现有有界、可取消行为。

## 数据与真实口径

| 页面信息 | 数据来源 | 呈现规则 |
| --- | --- | --- |
| “匹配报告” | 列表响应 `total` | 明确表示当前服务端分页查询的全量匹配数。 |
| “本页报告” | `items.length` | 仅描述当前页，不能外推至全部报告。 |
| “本页需优先复核” | 当前页中 `risk.high > 0` 的报告数 | 文案必须带“本页”；零项不应被解释为全局无风险。 |
| “本页高风险发现” | 当前页所有 `risk.high` 的求和 | 文案必须带“本页”；不计算平均风险或完成率。 |
| 报告类型、评分、风险分布、快照品牌、完成时间 | `ReportSummaryView` | 保留现有白名单字段、UTC 格式化和详情链接。 |
| 详情结论、覆盖范围、修复建议、重点风险、技术发现、趋势 | `ReportDetailView.render` | 只呈现已经校验且固化的 RenderModel 字段。 |

当列表为空时，保留当前查询与总数的上下文，但不渲染“本页 0”风险信号。`total === 0` 才表示“暂无安全报告”；`items.length === 0 && total > 0` 表示当前页在删除或数据变化后已无项目，必须显示“当前页没有报告”，保留总数、服务端页码和上一页操作，不能把它表述成系统没有报告。列表不增加客户端过滤、排序、搜索、日期筛选、批量导出或写入操作。

## 信息架构与视觉层级

### 列表页 `/reports`

自上而下采用四层：

1. **页头。** 保留“安全报告”及“不可变快照、服务端分页”的语义，补足管理者复核上下文。
2. **查询与本页复核面板。** 一个具名雾灰区域显示“当前查询”“匹配报告 {total}”及两个仅基于当前页的信号：需优先复核报告数、高风险发现数。无筛选能力时，查询标签只说明“全部报告”，不制造并不存在的筛选控件。
3. **不可变报告台账。** 保留原生 `table`、caption、列顺序、完成时间和查看链接。评分、风险分布和优先级以完整文字及 token 状态标记呈现，不依赖颜色表达语义。表格仅在自身 viewport 横向滚动。
4. **分页。** 保持既有 URL 正常化、服务端请求和按钮行为；窄屏允许纵向排列而不丢失可达性。

### 详情页 `/reports/:reportId`

详情不改变快照顺序和事实，仅调整阅读顺序：

1. **页头与导出。** 保留导出 PDF 的明确主操作、等待/失败状态和固定下载文件名。
2. **决策摘要。** 把现有风险摘要与覆盖、结论组合为首屏具名区域；安全评分、风险分布、评分说明、覆盖范围和结论都需可读、可复制，并明确来自该不可变快照。
3. **优先处置。** 修复建议与重点风险置于技术发现之前；现有高/中/低稳定排序和完整风险文字保持不变。
4. **技术证据与趋势。** 技术发现和 30 日趋势继续保留为独立语义区域。趋势仍使用原生台账，长文本折行。
5. **快照溯源。** 报告 ID、任务 ID、完成/生成时间、品牌快照、主色值和水印降为末尾的可追溯元数据区；不隐藏、不篡改历史值。主色值仅以已校验的 `#rrggbb` 文本展示，不作为新界面的硬编码视觉颜色。

在 960px 以下，列表的复核信号、详情的决策摘要和双列 metadata 收拢为单列；表格仅在局部横向滚动。不得生成卡片墙、装饰性图表、深色背景或硬编码颜色。

## 组件边界

新增的展示组件必须是本地、受控、无副作用的：

- `ReportPageReviewSummary`：输入当前页 `ReportSummaryView[]` 与服务端 `total`，唯一负责派生本页复核/高风险发现数量以及输出具名查询/信号区域；不请求、不改 URL。
- `ReportDecisionBrief`（若现有 `RiskSummary` 不足以维持清晰边界时）：输入固化 RenderModel 中已有的风险、说明、覆盖范围与结论；负责详情的首屏决策层，不导出、不过滤、不重排技术发现。

`ReportListPage` 保持 URL、查询、加载/错误/403/空态、表格列和分页职责。`ReportDetailPage` 保持路由、查询、导出取消与对象 URL 生命周期职责。现有 `RiskSummary`、`TechnicalFindings` 可在其安全 DTO 边界内重新布局或细化样式，但不得读取原始响应或新增数据字段。

## 状态、权限与安全边界

- **加载、403、失败：** 不显示列表查询总数或本页复核信号；继续使用现有 `StatePanel` 和显式重试。
- **列表空结果：** `total === 0` 时显示“暂无安全报告”；`total > 0` 且当前页没有项目时显示“当前页没有报告”，保留查询上下文、总数、服务端页码和可用的上一页操作。两种场景都不显示零值风险卡。
- **详情 403/404/失败：** 保留现有独立状态与无自动重试原则。
- **PDF 导出：** 保留单次写入保护、切换报告时取消旧请求、固定文件名、对象 URL 释放和失败后显式重试。
- **敏感数据：** 不把 API 原始 JSON、路径、token、logo、未白名单 metadata 或扫描输入放入 DOM、状态或测试 fixture。

## 无障碍与主题

- 查询、复核、决策摘要、技术发现、趋势、建议和快照元数据均使用具名语义区域；避免嵌套重复 landmark。
- 原生 `table`、caption、列标题与“查看报告 {id}”链接保持不变；状态完整说明保留在文本中。
- 所有新表面、边框、阴影、文本与风险状态使用 Fluent tokens。高风险使用警示/危险语义，低风险不得被误读为“完成”。
- 导出、分页和详情链接维持可见焦点、键盘可达和可读加载状态。

## 非目标与不可变约束

- 不改 `fetchReportList`、`fetchReportDetail`、`exportReportPDF`、报告解析器、URL 协议、query key、retry 策略或后端接口。
- 不新增报告编辑、删除、重算、批量操作、日期/关键字筛选、客户端排序、图表库或模拟指标。
- 不改任务、模型、知识库、侧栏、顶栏、全局主题或共享 `DataTable` API。
- 不触碰工作区中预先存在、未跟踪的 `.superpowers/` 目录。

## 验证策略

扩展现有 `ReportPages.test.tsx`，至少验证：

1. 成功列表中的具名查询/复核区域、服务端总数与本页风险口径；确认终端或零值不会被伪装为全局事实。
2. 原生表格、caption、列顺序、详情链接、可分享分页 URL、恶意参数归一化、`total === 0` 空库、`items.length === 0 && total > 0` 的越界当前页、加载/403/失败和分页继续通过。
3. 详情首屏能读到快照风险、覆盖范围、结论、建议与导出操作；重点风险的稳定排序、技术发现、趋势、快照元数据和 PDF 边界回归仍通过。
4. 真实浏览器在至少 1280px 与 390px 两种视口中验收：页面容器和正文不横向溢出；仅列表台账与详情趋势台账的局部 viewport 可横向滚动；导出、分页与查看链接仍可达。
5. 运行报告页定向 Vitest、`pnpm run lint`、`pnpm run typecheck`、`git diff --check` 和前端 Docker 全量门禁；登录后浏览器验收 `/reports` 与一份真实报告详情。
