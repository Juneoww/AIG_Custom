# AI 基础设施扫描专属工作台视觉设计

**状态：** 已与用户确认，待实施  
**分支：** `codex/ai-infra-scan`（基于 `develop`）  
**日期：** 2026-09-04  
**关联设计：** `2026-09-03-ai-infra-scan-design.md`、`2026-09-04-ai-infra-task-inputs-and-remark-design.md`。本文件定义专属任务台与新建页的视觉实现，不改变后两份设计中的功能、数据或权限边界。

## 1. 目标与范围

将 AI 基础设施扫描的专属任务台和专属新建任务页，从基础组件拼装的页面提升为与产品参考图一致的专业运营工作台。

本次范围：

- `/tasks/ai-infra` 专属任务台的页面层级、色彩、组件密度、状态视觉和响应式布局；
- `/tasks/ai-infra/new` 专属新建页的分步引导、目标输入布局、配置和确认区视觉；
- 两个页面共享的局部视觉令牌、状态样式、图标和工作台容器。

本次明确不包括：

- 全局侧栏、顶部栏、全局主题或其他任务类型页面的重新设计；
- 任务 API、筛选语义、权限规则、模型治理、目标校验和扫描引擎协议的视觉外功能变更；
- 将参考图中的侧栏、资产管理、任务模板等未确认信息复制进当前产品。

参考图是内容区视觉验收基线，不是额外功能需求。侧栏保持现状，因此不复刻参考图中的深蓝导航。

## 2. 设计原则

1. **局部而完整。** 只在 AI 基础设施扫描专属路径构建视觉工作台，避免影响全局控制台。
2. **运营信息优先。** 任务状态、待办和主操作优先于装饰；颜色必须传达状态而非只做点缀。
3. **真实数据语义。** 页面现有指标来自当前加载页和服务器精确筛选；视觉升级不得把当前页统计伪装成全量统计。
4. **安全边界不退让。** 不为丰富视觉将原始目标、模型凭据、附件内容或引擎数据引入任务列表。
5. **可访问且可收缩。** 文本对比度、键盘焦点、语义标签和窄屏单列布局必须保持可用。

## 3. 局部视觉系统

在专属页面下新增局部工作台令牌和样式，而不是修改全局 `ThemeProvider`。

| 用途 | 视觉方向 |
| --- | --- |
| 页面画布 | 轻冷灰蓝底色，增加内容区与卡片的层级。 |
| 主要操作 | 高对比钴蓝按钮，48 px 左右高度，带“新增”图标。 |
| 表面卡片 | 纯白背景、细冷灰描边、约 10–12 px 圆角、克制阴影。 |
| 运行态势 | 蓝（匹配）、绿（执行）、橙（等待）、红（关注）的低饱和背景与高可读数字。 |
| 表格状态 | 精确状态使用语义色标签：执行蓝、等待橙、完成绿、失败/待确认红、取消/调度中保持中性或明确差异。 |
| 图标 | 使用可访问的 Fluent 风格图标；装饰图标 `aria-hidden`，文字标签始终保留。 |

局部颜色值在样式模块集中声明，避免把色值散落到多个页面。若当前依赖中缺少所需图标，可引入官方 `@fluentui/react-icons`，不使用表情符号或图片代替业务图标。

## 4. 专属任务台 `/tasks/ai-infra`

### 4.1 页头与筛选

- 顶部采用更大的标题“AI 基础设施扫描”、一行简短副标题和右侧高显著性“新建 AI 基础设施扫描任务”按钮；
- 将当前文字链接升级为主按钮，但保留同一路由、权限判断和可访问名称；
- 状态筛选放入横向白色工具条，视觉上采用紧凑的状态胶囊/选择控件；
- 保持现有服务端单一精确 `status` 查询。不得为了复刻“需关注”胶囊而在浏览器端对分页数据进行伪筛选，或暗中改变为多状态 API；若展示汇总“需关注”，只将其作为运行态势指标而非不精确的筛选项。

### 4.2 运行态势区

使用四张等宽（窄屏自动缩为两列/一列）信号卡：

1. 当前查询匹配任务；
2. 本页正在执行（仅 `running`）；
3. 本页等待 / 调度中（`pending` 与 `dispatching`）；
4. 本页需关注。

“正在调度”不是“正在执行”：表格状态继续精确区分二者，运行态势也不将 `dispatching` 计入“正在执行”。每张卡包含圆形色块图标、标签、醒目数字和清楚的“当前页/当前查询”语义。指标继续复用现有安全任务摘要派生，避免额外请求、避免显示不存在的全量统计。

### 4.3 任务表与分页

- 任务台账置入一个带标题的白色工作台卡片；
- 表头采用轻灰底色、稳定列宽、舒展行高、清晰的横向分隔线；
- 状态标签使用具名语义色和小圆点，操作“查看”使用蓝色文本按钮/链接；
- 分页放在同一卡片底部，保留真实的总数、当前页和现有前后翻页行为；不展示与后端固定 `page_size=20` 不一致的“10 条/页”控件；
- `caption`、列头作用域、加载/空/错误/无权状态保持现有语义，不以纯视觉容器取代无障碍结构。

## 5. 专属新建页 `/tasks/ai-infra/new`

### 5.1 页面骨架

- 使用与任务台一致的标题区、返回任务台入口和局部工作台画布；
- 顶部显示三段式进度指引：“1 扫描对象 / 2 扫描配置 / 3 确认提交”；它是当前单页表单的信息架构提示，不隐藏字段、不引入不必要的多页向导状态；
- 每个步骤使用独立白色卡片、色彩编号或图标、简洁说明和更大的内部留白。

### 5.2 扫描对象卡片

按已确认的数据设计呈现：

- 左列为“手工填写扫描目标”；
- 右列为“导入目标清单（可选）”，具有清晰的上传区域、文件限制说明、上传按钮及已上传条目；
- 二者在视觉与语义上是并列目标来源，可任一或同时使用；
- 下方使用全宽的“任务说明 / 备注（可选）”字段，与目标输入明显区隔；
- 目标格式说明、示例、即时预览和授权范围提示收纳为蓝色信息面板，而不是散落的正文；
- 目标清单不再出现在独立“附件”步骤，通用任务页附件行为不变。

### 5.3 扫描配置与确认

- “扫描配置”卡片将受治理模型选择、超时和端口扫描模式组织为响应式字段网格；
- 固定 AI 端口说明用低强调辅助文本显示，全量 TCP 风险继续使用明确的警告组件；
- “确认并提交”卡片以摘要性提示、次要“取消”和主“创建 AI 基础设施扫描任务”按钮收束页面；
- 错误信息继续由现有 MessageBar 承载，但置于工作台内容区的固定可见位置。

## 6. 响应式与可访问性

- 大屏：运行态势四列，扫描对象手工输入与清单导入两列；
- 中屏：指标两列，表格保留横向滚动容器；
- 小屏：指标、字段和操作区均收为单列，主按钮占满可用宽度；
- 色彩不作为唯一状态信号：每个状态仍有文字与图标/标签；
- 所有新增图标、上传控件和步骤指引保留可访问名称、焦点样式和足够对比度；
- 不以截图精确像素为唯一标准，优先保证 320 px 至宽屏下的可读性。

## 7. 实现边界与回归保护

- 四张信号卡、工作台表格容器和专属页头使用 AI 基础设施专属组件或显式 `variant`；不得改写通用 `TaskOperationsSummary`、`DataTable`、`PageHeader` 的默认视觉，从而避免影响通用任务页和其他扫描类型；
- 通用 `DataTable`、`PageHeader` 仅在确有可复用且不影响其他页面的改进时调整；
- 路由、查询键、分页、筛选、权限、模型目录、附件 opaque ID、目标校验、幂等创建和取消逻辑不得改变；
- 与任务备注设计结合时，备注字段在新建页的视觉位置如上，但其后端独立存储、详情投影及不下发引擎的规则由关联设计定义；
- 不新增接口请求以填充纯展示数据；运行态势继续只使用已经取得的安全摘要。

## 8. 验收与验证

视觉验收：

- 在桌面宽度下，专属任务台具备明确的标题/主操作、筛选工具条、四色态势卡和白色台账卡层级；
- 新建页具备三段式信息引导、并列目标输入区和独立备注区；
- 页面内容区达到参考图的专业运营感，而侧栏未发生样式变化；
- 浅色、深色和窄屏模式均不出现低对比文字、溢出或重叠。

自动化验证：

- 更新任务台和新建页的 DOM/可访问性测试，锁定新增主按钮、步骤名称、目标清单语义和不变的查询/提交载荷；
- 针对状态标签和四个信号卡保留真实“当前页/当前查询”文案断言；
- 执行控制台 lint、类型检查、相关 Vitest、生产构建及 `git diff --check`；
- 在本地演示页以脱敏数据进行人工视觉检查，分别查看任务台和新建页。
