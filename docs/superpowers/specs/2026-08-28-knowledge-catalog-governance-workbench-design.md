# 规则资产治理工作台设计

## 背景与目标

“规则与知识库”汇集指纹规则、漏洞规则、安全评测集、MCP 插件、Prompt 集合和 Agent 配置六类真实资产。现有实现已经具备角色边界、服务端分页、原文按需读取、二次确认与原文不进入 Query cache 的安全基础，但页面仍以分散台账为主，分类导航和目录状态缺少统一的信息层级。

此次改造继续使用已确认的高级雾灰浅色体系。首个独立工作包把六类资产的入口组织为清晰的治理空间，并优先重构四个复用原生台账的规则资产页：指纹规则、漏洞规则、安全评测集和 MCP 插件。目标是让管理员和审计角色先判断当前资产范围、权限与目录状态，再进入筛选、原文查看和受审计治理动作。

设计不把目录数量解释为覆盖率、风险存量、运行健康度或同步成功率；这些事实没有由现有知识库接口提供，不能为了视觉效果而伪造。

## 备选方向与取舍

1. **只美化六个独立表格**：改动最小，但用户仍需在各页重新理解类别、范围和权限，无法形成统一的资产工作流。
2. **分类化资产工作台 + 查询感知目录简报 + 原生台账（采用）**：在不新增接口的前提下，把当前类别、服务端返回范围、当前页资产与角色权限明确分开；复用安全成熟的原文编辑流程，适合逐项审阅。
3. **跨六类资产的全局控制大屏**：看似能提供总览，但需要同时拉取不同分页/非分页接口，且无法正确推导完整全局数量、风险趋势或资产健康度；会增加无效请求和虚构指标，因此不采用。

## 范围与分期

### 第一包：分类壳层与规则资产台账（本设计覆盖）

- 更新 `KnowledgeLayout`，将六个路由入口分组为“扫描规则”“评测与扩展”“配置资产”，保留既有 URL、当前项状态和角色路由边界。
- 更新 `RawResourceLedger` 及其四个调用页：指纹规则、漏洞规则、安全评测集、MCP 插件。
- 增加只从当前成功目录派生的“资产目录概览”，梳理筛选、编辑区、空态/越界页、原生台账和分页的先后顺序。
- 在窄屏收束目录概览、筛选、编辑动作、分页与局部表格滚动；表格外页面不得产生横向滚动。

### 后续独立包（不在第一包实现）

- **Prompt 集合工作台**：单独处理其本地筛选、结构化能力边界、详情与表单的响应式布局及缓存错误态。
- **Agent 配置工作台**：单独处理模板、原文、连通性与 Prompt 测试的高风险交互层级和敏感输入生命周期。

### 不包含

- 不修改知识库 API、legacy 写接口、路由、服务端搜索/分页、权限、规则 schema、文件内容或同步流程。
- 不把原文、原文中的 Token/密钥/路径、MCP `RawData` 或 Agent 密码字段放入台账、摘要、Query cache、日志或任何新可见文本。
- 不改变所有已登录角色可读、仅管理员可创建/编辑/删除规则资产的既有授权规则；不扩展 MCP 目录的服务端筛选能力。
- 不将浏览器当前页统计称为全局统计，不新增跨分类总数、风险评分、覆盖率、运行健康度或同步结论。

## 信息架构

### 分类壳层

分类导航仍保留六个原路径，但用三个语义分组帮助用户先定位资产用途：

| 分组 | 资产 | 目标 |
| --- | --- | --- |
| 扫描规则 | 指纹规则、漏洞规则 | 识别与漏洞匹配依据 |
| 评测与扩展 | 安全评测集、MCP 插件 | 评测输入与扫描能力扩展 |
| 配置资产 | Prompt 集合、Agent 配置 | 应用检查与运行配置 |

导航是具名 `navigation` landmark。激活项保留可见文字、焦点与非颜色状态，且不把类别切换误表述为同步或发布操作。

### 规则资产页的成功态顺序

1. **页头与管理员动作**：保留资源名称、真实能力说明、下载样例/新增入口；只管理员看到写动作。
2. **资产目录概览**：具名 `region`，明确当前类别与目录来源。
   - 服务端分页资源（指纹、漏洞、评测集）显示 `匹配资源 {total}`、`服务器第 {page} 页`，并把 `items.length` 标为“本页资产”。
   - MCP 目录是现有接口一次性返回的完整目录，仅显示“当前目录 {total} 项”（需要辅助文案时使用“当前显示 {items.length} 项”）；进入 `/knowledge/mcp?page=…&q=…` 的深链会先正规化为类别根路径，且完整目录查询不会接收这些参数。页面不得出现“本页”“第 N 页”“服务器第 N 页”“上一页”或“下一页”，也不伪称服务端分页或可搜索。
   - 角色状态显示“可治理”或“只读查看”的文本/语义 Badge，但不把可治理当成安全、成功或健康度。
   - `total === 0` 时显示“暂无{资源}”，保留类别/目录上下文，不显示零值指标卡。
   - `items.length === 0 && total > 0` 的分页资源显示“当前页没有{资源}”，保留服务端总量、返回页码与可用上一页，不显示零值指标卡。
3. **筛选与编辑工作区**：有服务端搜索能力的三类资源保留 URL 驱动的筛选；打开原文查看、编辑或新建时，将既有 `StructuredEditor` 放入具名工作区。MCP 继续明确“不支持服务端筛选”。
4. **原生资产台账**：保留 `DataTable`、字段、资源 ID 与写动作。级别、范围或类别等已有确定枚举以语义 Badge/文字呈现，不能用成功绿替代含义。
5. **分页**：只为服务端分页目录显示，按钮以服务器返回的 `page` 与 `size` 决定；MCP 不展示虚假的翻页控件。

加载、403 和其他错误态只显示相应 `StatePanel`。一旦重新请求失败，目录概览、筛选结果、表格、基于旧行的查看/编辑/删除链接、总量和分页均不得继续从 React Query 的保留 `data` 渲染。用户此前主动打开的原文编辑工作区、保存确认或删除确认属于独立的交互状态机，不因目录刷新失败被强制关闭；它们仍必须遵守取消、卸载、Abort、互斥与原文清空规则。

## 组件与数据边界

新增纯展示组件 `KnowledgeCatalogBrief`：

- 输入为已校验的判别式安全显示范围、资源标签及当前角色的可治理布尔值。服务端分页范围可包含 `total`、`page` 与当前项目数；完整目录范围只能是 `total` 与当前项目数，类型上不含 `page` 或 `size`。
- 输出只包含当前类别、服务端返回的范围与明确的只读/可治理状态：服务端分页模式可显示当前页项目数和返回页码，完整目录模式只显示目录/当前显示项目数且不接收或渲染页码、页大小或翻页语义；不读取路由、不请求数据、不筛选、不排序、不保存原文或敏感字段。
- `RawResourceLedger` 继续负责 URL 正规化、TanStack Query、原文请求、下载、保存/删除确认与错误生命周期。

`RawResourceLedger` 仅建立一个安全的目录来源：

```ts
const catalog = listQuery.isSuccess ? listQuery.data : null
```

目录概览、空态、越界页、原生台账、行操作、总量和服务端分页控件都从 `catalog` 渲染，不能继续直接使用 `listQuery.data`。完整目录 fetch 的返回类型只含 `items` 与 `total`，不产生、不持有、不传入简报且不访问任何 `page`/`size` 字段。原文内容继续只存在于当前页面的本地状态，且在关闭、失败、资源切换或卸载时遵从既有清理流程。

## 视觉与响应式规则

- 只使用现有 Fluent UI token、语义 Badge 和高级雾灰浅色背景；不写硬编码颜色、装饰性渐变或伪图表。
- 桌面端：分组导航清楚但克制，目录概览置于台账之前，编辑区与表格使用低对比边框和留白区分，不制造额外卡片噪声。
- 960px 以下：导航组、目录概览、筛选控件和服务端分页均收拢为单列或可换行布局；编辑器操作组允许换行/纵向排列。
- 390px：仅 `DataTable` 的局部 `tableViewport` 可横向滚动，页面根节点不能溢出；表格行操作换行，分类链接保持可点击和可见焦点。
- 所有重要区域使用具名 landmark、原生表格/表单语义和可见焦点；颜色不能单独表达资源类型、可写性或严重性。

## 测试与验收

### 自动化

- `KnowledgeCatalogBrief`：验证服务端分页与完整目录的不同文案、角色可治理/只读状态、空集合及分页资源的越界空页；完整目录不得渲染任何页码、页大小或翻页语义，也不得出现全局风险或虚构健康度。
- `KnowledgePages`：在指纹目录成功加载后使同一查询重取 403 与 500，断言旧概览、表格、行操作、总量、页码和分页均消失，只保留安全错误态；保留已打开编辑/确认状态的独立性。
- 验证 MCP 不渲染筛选和虚假分页，带 `page`/`q` 的 MCP 深链被正规化且不会把这些值送入完整目录查询；三个服务端分页资源保持 URL 筛选、服务器返回页码和可用上一页。
- 保留现有角色矩阵、原文不进 Query cache、原文按需读取、保存/删除二次确认、Abort/互斥和安全错误文案测试。
- 运行知识库定向测试、lint、typecheck、差异检查和 Docker Node 22 前端完整门禁。

### 浏览器验收

在用户登录的本地预览中，以管理员与审计员在 1280px/390px 检查：

- 1280px：分类用途、当前资源范围、可治理/只读边界和台账层级一眼可读，管理员动作未向其他角色泄露。
- 390px：分类导航、筛选、目录概览、工作区和分页无页面横向溢出；仅表格可局部横向滚动。
- 成功加载后触发权限或服务错误时，旧目录和链接不会留在错误面板后；原文、Token、密钥、路径和 RawData 不进入目录概览或 Query cache。
