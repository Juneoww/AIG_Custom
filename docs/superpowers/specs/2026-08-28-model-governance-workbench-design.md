# 模型治理工作台设计

## 背景与目标

“模型与凭据”是管理者配置扫描与评测能力的入口。现有页面已经严格处理了角色权限、Token 脱敏、服务端分页和单次写请求，但视觉上仍是单一台账。此次改造沿用已确认的高级雾灰浅色体系，将页面调整为**先判断当前可治理范围，再进入模型台账和配置动作**的工作台。

目标是让管理者在不暴露已保存 Token、不伪造全局运行指标的前提下，一眼读出当前查询的目录规模、可配置模型、停用项与只读项。

## 备选方向与取舍

1. 只调整台账样式：实现最小，但不会改善治理判断效率。
2. 查询感知的治理简报 + 原生台账（采用）：服务端总量与当前页信号明确分开，能支撑管理者快速判断，同时保持数据边界诚实。
3. 全局模型健康大屏：视觉吸引力高，但当前 API 没有全量状态、调用成功率或凭据健康度，容易制造不真实的指标，因此不采用。

## 范围

### 包含

- `/models` 的页头、当前查询治理简报、台账、分页和创建/编辑表单的视觉层级与响应式布局。
- 将目录中的既有事实转化为当前页信号：可配置 platform 模型、已停用模型、只读项。
- 使成功缓存随后在 403/500 重取失败时不再继续呈现旧目录、操作链接、总量或分页。
- 为窄屏把台账横向滚动限制在表格视口，将分页和表单收拢为单列。

### 不包含

- 不新增或修改任何模型 API、路由、查询参数、服务端权限、Token 保存/轮换方式。
- 不显示、缓存或推导**已保存的** Token 值、掩码、主密钥、连接健康度、调用量、成功率或全局可用性。创建/编辑表单保留既有的密码输入与标签；输入值只在该表单的短暂本地状态中存在，并在取消、失败、成功或卸载时清空，绝不进入 DTO、Query cache、台账、日志或可见文本。
- 不改变 YAML/数据库模型并存、同 ID 区分、用户仅管理私有 platform 行、管理员仅管理全局 platform 行的既有权限规则。
- 不把客户端当前页统计标注成全局统计，也不在浏览器端筛选服务器返回的目录。

## 信息架构

成功态按以下顺序呈现：

1. **页头与创建动作**：维持“模型与凭据”标题、角色化创建按钮及 Token 不回传说明。
2. **模型治理态势**：具名 region，分为“当前查询”和“本页治理信号”。
   - 当前查询永远显示服务端 `total`（文案为“匹配模型”）及服务器返回页码。
   - 本页治理信号仅在 `items.length > 0` 时显示：可配置模型（`canManage(role, item)` 为真的 platform 行）、已停用（`item.disabled`）、只读项（`item.read_only`，包括 YAML 和因角色限制而只读的 platform 行）。三者是独立计数，允许同一行同时被计入多个信号。
   - `total === 0` 时显示“暂无可见模型”，保留当前查询但不显示零值信号。
   - `items.length === 0 && total > 0` 时显示“当前页没有模型”，保留服务端总量/页码和可用上一页，不显示零值信号。
3. **配置工作区**：创建或编辑时，将既有表单放入有标题的轻量工作区。Token 的一次性提交、清空与不回填语义保持不变。
4. **受治理模型台账**：保留原生 DataTable、既有列和角色化动作；来源、作用范围和状态使用语义 Badge，不能以绿色暗示安全或成功。
5. **分页**：继续完全由 URL 和服务端页码驱动。

加载、403 和其他失败态只呈现对应 `StatePanel`；治理简报、台账、链接、总量和分页均只从当前成功查询派生，不能从 React Query 保留的旧 `data` 派生。已经由用户主动打开的创建/编辑表单、删除确认或轮换对话框不由目录刷新强制关闭，继续遵守各自既有的取消、权限与错误状态机。

## 组件边界

新增 `ModelCatalogGovernanceSummary` 作为纯展示组件：

- 输入为已校验的 `ModelCatalogPage`、当前角色和 `canManage` 的可复用判断。
- 输出只包含 `匹配模型`、服务器页码和当前页的三类独立治理信号（可配置、已停用、只读项）。
- 不请求数据、不读路由、不保存敏感值、不负责筛选或排序。

`ModelListPage` 继续负责 URL 正规化、TanStack Query、角色操作、删除/轮换状态机与表单开关；将成功态目录赋给唯一的 `modelCatalog` 变量，所有数据派生 UI 都从它渲染。

## 视觉与响应式规则

- 只使用 Fluent UI token 与语义 Badge；沿用浅色高级雾灰背景、深色文字、鼠尾草/铜色/语义色点缀，不写硬编码颜色。
- 治理简报采用低对比卡片与清晰分组，桌面端信息密度适中；不使用伪图表或装饰性渐变。
- 960px 以下：治理简报信号单列，页面分页从两端对齐收拢为纵向，表单字段单列。
- 390px：台账仅在自身 `tableViewport` 内横向滚动，页面根节点不产生横向滚动；操作按钮允许换行。表单可见密码输入的值仍保持遮蔽，已保存 Token、掩码和凭据文本不出现在页面。
- 所有区域使用具名 landmark、原生表格语义和可见焦点，不用颜色单独表达来源、状态或可写性。

## 测试与验收

### 自动化

- 成功目录：断言 `模型治理态势`、服务端总量、当前服务器页码、三种当前页信号、原生台账和 URL 分页。
- 空集合与越界空页：分别断言不显示信号、且越界时保留总量与可用上一页。
- 冷启动及缓存后重取的 403/500：断言只出现安全状态，绝不保留旧简报、台账、链接、总量或分页。
- 纯组件：验证当前页信号的精确谓词、允许重叠与“仅当前页”的边界；不把 YAML 或角色只读 platform 行计入可配置模型。
- 保留现有角色矩阵、Token 清空、删除/轮换取消、表单禁用确认和安全 DTO 测试。
- 运行模型定向测试、lint、typecheck、差异检查以及 Docker 前端完整门禁。

### 浏览器验收

登录后的预览中分别在 1280px 和 390px 检查管理员与审计员视图：

- 1280px：简报先于台账，可写/停用/只读边界一眼可读，角色动作未越权。
- 390px：简报、表单和分页单列；只有表格局部横向滚动；密码输入及标签可见，但已保存 Token、掩码和凭据文本不出现在页面。
- 在成功加载后触发权限或服务错误时，确认旧台账不会留在错误面板后。
