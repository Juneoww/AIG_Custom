# 登录页「高级雾灰」重设计

日期：2026-08-25  
状态：已获视觉方案批准，待实现计划  
范围：企业控制台的 `/login` 页面（第一阶段）

## 背景与目标

现有登录页是一个偏左的小型表单卡片，页面留白失衡，无法传达 AI 安全治理产品应有的可信感和专业度。用户已明确选择：

- 全站方向为浅色，不采用深色视觉；
- 视觉语言选择「高级雾灰」：暖白底、墨蓝文字、低饱和的鼠尾草绿和棕金状态点缀；
- 采用逐页推进的方式，先完成登录页。

本阶段的目标是在不改变认证能力的前提下，建立一张具有品牌感、适合长时间使用、在桌面和窄屏下均清晰可用的登录页。

## 已讨论的方案

1. **清透蓝白**：最接近常见的专业 AI 平台，信息清晰但品牌辨识度较弱。
2. **高级雾灰（选定）**：以暖白、雾灰、墨蓝为主，通过留白、排版和细微材质建立高级、克制的治理工作台感。
3. **轻盈蓝绿**：更强调实时态势和产品活力，但对合规、治理类场景略显轻快。

选择方案 2。它既避免传统后台的冰冷感，也不会把安全产品做成高压的深色 SOC 面板。

## 视觉与布局设计

### 画布和色彩

- 全屏暖灰画布：主背景接近 `#F5F5F2`，以极浅的雾绿和暖米色径向光晕制造层次；不得使用大面积纯白或黑色背景。
- 细密但低对比的网格纹理只作为左侧氛围层，不能影响表单阅读。
- 文字主色为墨蓝灰（约 `#1C2839`）；主按钮为 `#2C415D`；鼠尾草绿与棕金只能用于可信状态、装饰节点或强调，不承担正文信息。
- 不新增远程字体、图片 CDN 或跟踪资源。继续使用项目内的 Droid Sans Fallback、Microsoft YaHei UI 和既有本地字体。

### 桌面布局（≥ 951px）

- 顶部细工具栏：左侧沿用运行时品牌名与 Logo；右侧显示非交互的“受控本地访问”可信提示。
- 内容区采用约 `55 / 45` 的双栏布局：
  - 左栏是产品叙事，不是营销落地页：简短的“可信 AI 运营”标识、一句治理价值主张、三项能力（资产可见 / 风险可控 / 治理可证）。
  - 右栏是 420–440px 的登录卡。卡片位于视觉重心，使用半透明暖白表面、细边框、柔和阴影和顶部的窄色带。
- 登录卡内包含品牌标记、`登录平台` 标题、既有说明、认证错误、两个表单字段、主按钮、重置凭据链接和简短审计说明。
- 左栏仅使用抽象轨道和节点装饰；它们必须 `aria-hidden`，不能表现实时安全数据，避免误导用户。

### 窄屏布局（≤ 950px）

- 改为单列；卡片在页面上方或主视觉之后保持首要位置。
- 叙事区缩小；抽象轨道与不必要的装饰隐藏。
- 表单可用宽度完整保留，触控高度不少于 44px，页面允许自然纵向滚动。

## 组件边界与行为保持

仅重构 `web/console/src/features/auth/LoginPage.tsx` 的 DOM 结构和局部 Fluent `makeStyles` 样式；不要修改路由、会话、API 客户端、CSRF、主题 Provider 或后端。

下列现有行为和可访问性契约必须不变：

- `usePublicBrand()` 的 `productName` 与 `logoDataURL` 继续作为品牌唯一来源；没有 Logo 时仍显示“安”字回退。
- 页面主标题仍为“登录平台”；字段可访问标签仍是“用户名”和“密码”；输入框的 `autocomplete` 分别为 `username`、`current-password`。
- 登录按钮仍显示“登录”，在用户名为空、密码为空或提交中禁用；可以增加不改变名称的图标/箭头装饰。
- `/reset-password` 链接保留；现有 `RequireAnonymous` 的成功跳转不变。
- 保留并发提交防抖、失败时清空密码而保留用户名、认证/网络/安全传输错误映射，以及不持久化任何凭据的行为。
- 错误信息仍由可访问的 `MessageBar` 传达，并位于字段之前；视觉上收敛成暖色细边提示，不能仅依靠颜色表达失败。

## 实现要点

- 在 LoginPage 内新增语义化样式块：`page`、`topbar`、`story`、`trustPillars`、`authPanel`、`authHeader`、`footerNotice` 等，避免把页面样式泄漏到 `global.css`。
- 继续使用 Fluent v9 的 `Field`、`Input`、`Button`、`MessageBar` 与 `Text`，保证现有行为和焦点管理；必要时用普通语义元素包裹布局。
- 只在此页面引入暖灰色值。第一阶段不修改 `shared/theme/tokens.ts` 和 `shared/styles/global.css`，以免影响已经登录后的页面和现有深色主题测试。后续全站重设计时再统一迁移主题令牌。
- 视觉装饰禁止接入真实资产、扫描、用户或审计数据；认证页在未登录状态只展示静态产品说明。

## 错误处理

- 提交期间保持字段禁用和按钮状态，防止重复登录；不得因样式重组丢失此状态。
- 认证失败后：展示既有中文提示、用户名保留、密码清空并可继续编辑。
- 网络或 HTTPS 安全传输失败后：显示既有安全提示；不在客户端绕过生产 HTTPS / CSRF 限制。8089 仅是隔离测试预览。
- 小屏、长品牌名和缺失 Logo 均不能导致卡片溢出或遮挡登录字段。

## 验证与验收

### 自动验证

优先运行：

```powershell
Set-Location web/console
pnpm run prepare:fonts
pnpm exec vitest run src/features/auth/pages.test.tsx
```

如更新了语义断言，再运行相关的路由/会话测试；完整前端验证使用仓库已有的 console test compose。最终在隔离预览中人工确认桌面与窄屏布局。

### 验收标准

- 登录页在 1440px 桌面宽度下呈现暖白双栏构图，表单卡不再贴左或被大量无意义空白包围。
- 页面没有深色背景、大面积高饱和蓝色或外部字体/图片依赖。
- 用户可以通过键盘完成用户名、密码、登录和重置凭据链接的访问；焦点可见。
- 现有 auth 单测和 E2E 所依赖的文本、标签、按钮状态及登录错误行为均保持通过。
- 功能改动只限登录页，已登录控制台页面的视觉与主题行为不发生变化。

## 非目标

- 本阶段不重做首页、侧栏、扫描任务、风险详情、设置页或全局主题。
- 不删除现有暗色主题支持；全站浅色化会在后续页面设计批准后处理。
- 不修改鉴权策略、账户模型、密码重置协议、审计存储或 Docker 部署配置。
