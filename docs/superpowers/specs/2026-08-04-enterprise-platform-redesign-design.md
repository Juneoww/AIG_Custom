# 企业安全平台二开设计

## 1. 目标与边界

将 AI-Infra-Guard 的现有扫描能力包装为独立品牌的企业安全平台。第一期重点是全新用户界面、账号密码登录、权限治理、管理层报告和国产化部署适配；AI Infra Scan、MCP Scan、Agent Scan、Prompt/Jailbreak Evaluation 的扫描逻辑、规则库和结果判定保持不变。

平台为单租户，仅服务一个组织。产品名称、Logo 和蓝色主色均应可配置；第一期使用新生成的独立品牌标识，不沿用 A.I.G 品牌视觉。

## 2. 总体架构

采用“新平台壳层 + 既有扫描引擎”的渐进式架构：

- 新前端提供企业工作台式 UI、登录、权限、任务和报告页面。
- 新平台 API 负责认证、授权、用户与角色、审计日志、品牌配置、报告快照、PDF 导出，以及向扫描引擎发起内部任务。
- 既有 Go/Python 扫描器保持为内网执行引擎；第一期不重写其规则、检测策略或任务实现。
- 浏览器只访问新平台 API；旧 Web/API 与 Agent WebSocket 仅可由内网、受控服务访问，后续逐步迁移或下线。

## 3. 身份、权限与审计

账号不开放自助注册，由系统管理员创建并分配角色。部署时以初始化命令创建首个管理员。

密码以 Argon2id 存储。首次登录、管理员重置密码后必须修改密码。平台使用安全会话 Cookie（HttpOnly、Secure、SameSite）与 CSRF 防护，禁止将 `username` 等请求头作为身份依据。

| 角色 | 权限 |
| --- | --- |
| 系统管理员 | 管理用户、角色、全局模型、规则库、品牌/系统配置；查看和管理全部任务、报告与审计日志。 |
| 普通用户 | 创建、查看和管理本人任务、模型、附件和报告。 |
| 安全审计员 | 查看全平台任务与报告、导出报告；不能创建、修改或删除资源。 |

所有登录、失败登录、密码重置、用户/角色变更、任务变更、报告导出与系统配置变更记录审计日志。任务和附件默认私有；如后续提供分享，应使用显式、可撤销和可过期的分享记录。

模型配置分为两类：管理员维护可供全平台使用的全局模型；普通用户仅可创建、修改和删除本人私有模型，且仅可在自己的任务中引用。私有模型不对其他普通用户或审计员展示；管理员为治理目的可查看元数据、禁用配置，但不直接展示已加密的密钥材料。模型密钥以独立于页面响应的加密存储处理。

## 4. UI 与页面范围

整体视觉采用浅色、克制、信息密度高的企业工作台风格，蓝色为主色。第一期页面包括：

- 登录、首次改密、个人中心；
- 安全总览：安全评分、风险趋势、风险分布、最近任务与待办处置；
- 扫描任务：创建、列表、详情、实时状态、结果；
- 安全报告：列表、在线详情、PDF 导出；
- 模型配置、规则与知识库；
- 管理员专属的用户与角色、审计日志、品牌与系统设置。

菜单和数据按角色控制。普通用户仅看到自己的数据；审计员看到全局只读数据；管理员看到治理与配置入口。

## 5. 报告设计

报告采用“管理层摘要优先”结构：

1. 安全评分、评分说明和风险趋势；
2. 风险分布、Top 风险和优先处置建议；
3. 扫描覆盖范围、任务元数据和结论；
4. 可下钻的技术发现、证据、影响和修复建议。

在线报告与 PDF 从相同的报告快照渲染，保证规则更新后历史报告不被改变。PDF 包含产品名、Logo、生成时间和预留水印位置，并使用适用于中文环境的字体。

当引擎成功持久化任务结果后，平台自动生成一份不可变报告快照；导出失败可针对同一快照重试，不重算报告内容。任务重新执行会创建新的平台任务和新的报告快照，不覆盖原任务或其报告。只有系统管理员通过受审计的修复操作，才可在保留旧版本的前提下补建缺失快照。安全评分与风险项由引擎结果中的风险等级和命中项映射得出，并将映射版本写入快照；总览趋势使用最近 30 天已完成任务的快照统计。

## 6. 数据与任务

保留原扫描器的任务执行和规则数据。新平台新增用户、角色、会话、审计日志、品牌配置、报告快照及导出记录等数据。

当前阶段以 PostgreSQL 作为开发、测试和交付环境的唯一支持数据库。数据库访问层使用版本化迁移和明确配置，关键写入使用事务；避免将 SQL 方言假设扩散到业务层，为后续达梦适配保留边界，但当前不引入达梦驱动、镜像或迁移验证。

扫描引擎失败、Agent 失联或 PDF 生成失败时，必须保留任务状态、错误原因和已生成的报告快照，不丢失历史数据。

新旧系统间以受控的“引擎适配器”隔离：平台 API 仅调用 `SubmitTask`、`GetTaskStatus`、`GetResult` 与受控 `CancelTask` 接口；适配器将平台任务映射为既有引擎的任务格式，并通过内网专用凭据调用旧服务。平台先持久化任务、所有权和输入附件元数据，再由适配器分发；适配器回传状态和结果时以平台任务 ID 关联，不接受浏览器直接回调。附件由平台受控存储并以短时内部引用传递，扫描结果则由适配器拉取或经已认证的内部回调写回。分发采用幂等键处理可重试的网络/队列故障；已进入引擎的扫描失败不自动重跑，保留失败原因并由有权用户显式创建新任务重跑。

## 7. 国产化与部署

第一期优先适配麒麟 Linux 的 Docker 部署，所有服务和构建/测试工具均以容器运行，宿主机仅需 Docker Engine 与 Compose：

- 提供 `linux/amd64` 与 `linux/arm64` 镜像；
- 提供离线镜像导入、配置和升级说明；
- 镜像内包含中文字体与 PDF 所需运行依赖；
- 运行 Compose 包含 `platform`、受控 `agent` 和持久化 `postgres` 三个常驻服务；`migrate` 是一次性迁移容器，不设置独立前端、Redis 或数据库管理 UI 服务；
- 当前运行、开发和测试均使用 PostgreSQL；
- 不依赖海外 SaaS，模型和第三方服务保留可配置的本地/私有地址接入能力。

## 8. 验收与测试

- 单元/集成测试覆盖密码处理、会话、三角色权限、越权访问、任务所有权、审计日志、报告快照和 PDF 导出。
- 在 PostgreSQL 上验证迁移与核心读写，并以 Docker Compose 验证 `platform`、`agent`、`postgres` 与一次性 `migrate` 服务。
- 对 `linux/amd64` 和 `linux/arm64` 构建 Docker 镜像；在麒麟 + PostgreSQL 环境完成部署冒烟。
- 对扫描引擎适配接口做回归，确认相同输入在平台改造前后产生同类任务和扫描结论。

## 9. 非目标

- 第一期间不重写扫描规则、检测引擎或 Python 扫描流程。
- 第一期间不实施多租户、外部 SSO、开放注册或微服务拆分。
- 第一期间不承诺将旧公开 API 保持为浏览器可访问接口；旧接口仅作为内部兼容层逐步收敛。
- 达梦驱动、方言迁移、镜像及麒麟 + 达梦联合验收延期到后续阶段，待目标版本和供应商交付物确定后另立设计与实施计划。
