# MCP 工作台与新建任务页设计

**状态：** 已确认交互原型，待用户审阅本文档

**分支：** `codex/mcp-scan-workbench`（基于 `develop`）

**日期：** 2026-09-03
**范围：** MCP 安全扫描工作台、MCP 专属新建任务页及其浏览器接口边界。

## 1. 目标与边界

本设计让用户从 **MCP 安全扫描工作台** 发起一项 MCP 专项任务，并在整个过程中保持 MCP 业务边界。它不复用 AI 基础设施扫描、模型红队或 Agent 工作流的页面、路由和浏览器任务接口。

已确认的原则：

- 进入 MCP 新建任务页后，任务类型固定为“**MCP 安全扫描**”；页面内不显示、更不允许切换其他任务类型；
- 支持两类扫描对象：**代码 / 仓库扫描** 与 **受控运行服务扫描**；
- 运行服务的端点、Token、Header 和 TLS 相关接入信息只在“凭证配置 → MCP 连接配置”中维护；新建任务页只选择已启用、当前版本测试成功的配置；
- 输出语言固定为中文，页面不展示语言选择器；
- 工作台保留 MCP 专属的指标、近期任务与重点风险，不能混入其他扫描域的任务或风险；
- 后端可以在内部复用既有持久化、身份、审计、附件与 Agent 调度能力，但 MCP 的路由、Handler、浏览器 DTO 和类型校验必须独立。

MCP 连接配置的字段、版本、测试、出站控制与凭证脱敏规则由 [MCP 连接配置设计](2026-09-03-mcp-connection-configuration-design.md) 定义；本文只定义任务页如何使用它。

## 2. 信息架构与路由

| 页面 | 路由 | 用途 | 允许进入的下游页面 |
| --- | --- | --- | --- |
| MCP 安全扫描工作台 | `/tasks/mcp` | 查看 MCP 专属概览、近期任务和风险，并发起任务 | `/tasks/mcp/new`、MCP 专属列表/风险视图、`/tasks/mcp/:taskId` |
| 新建 MCP 扫描 | `/tasks/mcp/new` | 固定 MCP 任务类型，选择对象、配置并确认创建 | 凭证配置、MCP 专属详情 |
| MCP 扫描详情 | `/tasks/mcp/:taskId` | 查看该 MCP 任务的进度、结果、报告与安全摘要 | 返回工作台 / 同域页面 |
| MCP 连接配置 | `/credentials/mcp-connections` | 管理连接端点、传输方式、认证及测试状态 | 返回新建页的可选配置 |

浏览器不得以 `task_type`、`source_kind` 等 query 参数决定 MCP 新建页的任务类型，也不得从 `/tasks/mcp/new` 跳转到通用 `/tasks/new`。全局侧栏仍可用于导航到其他已存在的独立业务域，但 MCP 页主体内没有任务类型切换器。

```text
/tasks/mcp
  └─ 点击「+ 新建 MCP 扫描」
       └─ /tasks/mcp/new
            ├─ 代码 / 仓库扫描 → Git 地址 或 代码附件
            └─ 受控运行服务扫描 → 选择 MCP 连接配置
                 └─ 创建成功 → /tasks/mcp/:taskId
```

## 3. MCP 安全扫描工作台

### 3.1 页面组成

工作台在单一 MCP 域中展示以下内容：

1. 页面标题与说明：`MCP 安全扫描工作台`，说明其覆盖 MCP 代码和受控运行服务；
2. 操作区：
   - 主操作 `+ 新建 MCP 扫描`，进入 `/tasks/mcp/new`；
   - 次操作 `MCP 连接配置`，进入 `/credentials/mcp-connections`；
3. 指标区：执行中的扫描、待处理风险（需突出高风险数量）、近 30 天完成扫描、受管 MCP 覆盖率；
4. 最近扫描任务：名称、扫描对象、状态、风险摘要，以及进入 MCP 任务详情的链接；
5. 重点风险：按 MCP 专项风险类别聚合的数量与时间范围；
6. MCP 内部切换入口（例如“工作台 / 扫描任务 / 风险发现”），其数据范围始终为 MCP，不借此切到其他任务类型。

覆盖率应清楚标明分母口径（例如“已覆盖受管 MCP 服务 / 受管 MCP 服务总数”），无资产台账或无法计算分母时显示 `—` 和原因，不得伪造百分比。

### 3.2 状态与可用性

- 首次加载：使用指标卡、任务表和风险卡的骨架屏；
- 无任务：仍显示主操作，并明确提示尚未创建 MCP 扫描；
- 无权查看某一数据集：保留页面框架，但该区块显示无权限，不以空数据伪装；
- 工作台局部加载失败：仅该区块可重试，已成功加载的其他区块不清空；
- 任务状态、风险数量和覆盖率仅呈现服务端返回的 MCP 专属安全摘要。

## 4. 新建 MCP 扫描页

### 4.1 固定任务边界和步骤

页面标题为“新建 MCP 扫描”，副标题说明任务类型已固定。页面用四步进度说明用户所在流程：

1. 扫描对象；
2. 扫描配置；
3. 确认创建；
4. 任务详情。

进度指示帮助理解流程，不赋予用户切换到其他扫描域的能力。取消返回 `/tasks/mcp`，不保留未创建的服务凭证或附件。

### 4.2 扫描对象选择

在“选择扫描对象”区使用两个互斥卡片：

| 对象 | 用户输入 | 不显示 / 不提交 |
| --- | --- | --- |
| 代码 / 仓库扫描 | Git 仓库地址 **或** 已上传代码附件 | MCP 连接配置、端点、Token、Header、服务授权确认 |
| 受控运行服务扫描 | 已授权 MCP 连接配置 | Git 仓库地址、代码附件、端点、Token、Header、TLS 覆盖项 |

切换对象时，客户端清除与新对象不兼容的临时输入；服务端也必须拒绝不兼容字段，不能依赖客户端清理。

#### 代码 / 仓库扫描

- Git 仓库 URL 与代码附件互斥，且至少存在其一；
- Git 地址首期仅允许 `https`，不得包含 UserInfo、Query、Fragment 或内嵌凭据；执行前解析 DNS，拒绝环回、链路本地、组播、未指定、云元数据及不在部署管理员配置的 Git 出站允许集合内的地址；禁止跨允许边界的重定向和子模块自动拉取；
- 附件必须先完成 MCP 专属上传、归属和安全检查，才可选择创建；
- 页面显示来源类型、已选附件名/数量或已校验 Git 地址，但确认摘要不展示可能包含敏感信息的原始访问凭据；
- 本期不在任务页配置私有 Git 凭据。代码来源不显示 `authorization_confirmed` 复选框是明确的产品决定：只能扫描平台允许的 Git 主机或当前主体拥有的已上传附件，服务端据此执行来源 ACL 与审计；任意公共 URL、私有 Git 凭据和自由网络探测均不在首期范围。

#### 受控运行服务扫描

- 连接选择器只调用“任务可选连接”资源，只展示当前主体可用、已启用且当前版本测试成功的配置；每项包含不可编辑的安全 `version`，创建时与配置 ID 一起提交；响应 ETag 只用于选项列表缓存失效；
- 每个选择项只显示安全标签：配置名称、传输方式、认证方式摘要、启用/测试状态；不显示实际端点、Token、Header、Cookie、证书、原始测试响应；
- 无可用配置时，展示“前往 MCP 连接配置”的治理入口，而不是在任务页补充凭证字段；
- 用户必须勾选“我确认已获得该目标的安全测试授权”。这是一项独立于连接配置的声明；
- 服务扫描不允许有附件或原始端点字段。

### 4.3 通用扫描配置

两类来源共享以下配置：

- **扫描模型（可选）**：只从受治理模型目录选择，也可以是“不使用模型”；模型选择不是 MCP 连接配置，也不带出模型密钥；
- **并发数**：默认展示 `4`，实际可选范围由服务器返回/校验；
- **输出语言**：固定显示“中文”，浏览器不提供变更控件，服务器只接受/写入 `zh_CN`；
- **创建按钮**：只有当前来源的必填条件成立时才可用。点击后立即进入提交态，防止重复创建。

### 4.4 确认摘要与提交结果

确认阶段只展示可复核的安全摘要。

| 项目 | 代码 / 仓库扫描摘要 | 受控运行服务扫描摘要 |
| --- | --- | --- |
| 扫描对象 | 代码 / 仓库 | 受控运行服务 |
| 来源 | Git 仓库或已上传代码包 | 连接配置名称、传输方式、认证方式摘要 |
| 模型 / 并发 / 输出 | 已选模型或不使用模型、并发、中文 | 相同 |
| 授权 | 不适用 | 已确认安全测试授权 |

创建成功后使用服务端返回的 MCP 任务 ID 跳转到 `/tasks/mcp/:taskId`。创建失败时保留非 secret 表单值和可重试状态；网络结果不确定时不得自动再次提交，用户明确点击“查询创建结果 / 重试”时才用**相同** `Idempotency-Key` 重发相同请求，以获得原始结果而非新建第二个任务。

## 5. MCP 专属浏览器 API

所有路径以下列 MCP 专属资源为准，不调用通用 `/api/v1/platform/tasks` 或 AI 基础设施扫描的任务接口。

### 5.1 通用任务接口的切换规则

专属接口上线后，新版浏览器对于 `mcp_scan` 不再调用通用任务接口。旧页面路由 `/tasks/new?task_type=mcp_scan` 在客户端执行 `replace('/tasks/mcp/new')`，忽略并清除 `source_kind` 等旧 query；旧 MCP 任务 ID 由新 `GET /mcp-scans/:taskId` 直接读取同一内部任务记录，无需迁移或复制数据。

通用浏览器接口在发现 `task_type=mcp_scan` 或目标任务为 MCP 类型时，返回 `409 MCP_SPECIALIZED_ENDPOINT_REQUIRED` 和安全的 `specialized_path`，不再返回通用任务 DTO，也不接受创建。非 MCP 任务行为保持不变。实现时必须同步更新中英文 API 参考文档和 Swagger 运行时三件套，并覆盖旧路由重定向、旧 MCP ID 读取、新旧接口拒绝边界的回归测试。

| 操作 | 接口 | 说明 |
| --- | --- | --- |
| 工作台概览 | `GET /api/v1/platform/mcp-workbench` | 指标、近期任务、重点风险的 MCP 专属安全投影。 |
| MCP 任务列表 | `GET /api/v1/platform/mcp-scans` | 支持分页、状态筛选；不返回非 MCP 任务。 |
| 创建 MCP 任务 | `POST /api/v1/platform/mcp-scans` | 只接受下述 MCP 创建 DTO；需 CSRF 与幂等键。 |
| MCP 任务详情 | `GET /api/v1/platform/mcp-scans/:taskId` | 只返回 MCP 任务的安全详情。 |
| 取消 MCP 任务 | `POST /api/v1/platform/mcp-scans/:taskId/cancel` | 复用任务取消调度，但使用 MCP Handler 与授权校验。 |
| MCP 代码附件 | `POST /api/v1/platform/mcp-scan-attachments` 及其分片、合并和删除子路径 | 只返回 opaque 附件 ID；不借用通用任务附件路径；首期不提供浏览器下载源码附件。 |
| 可选 MCP 连接 | `GET /api/v1/platform/mcp-connection-options` | 只返回可用、启用且当前版本测试成功的安全摘要及每项 `version`；响应 ETag 仅用于缓存失效。 |
| 受治理模型目录 | `GET /api/v1/platform/models` | 用于模型下拉；不作为通用任务创建接口。 |

创建请求按来源使用严格互斥的形状：

```json
{
  "source": {
    "kind": "repository",
    "repository_url": "https://git.example.internal/team/mcp-server.git"
  },
  "attachment_ids": [],
  "model_id": "optional-opaque-model-id",
  "thread": 4,
  "country_iso_code": "zh_CN"
}
```

代码附件模式以非空 `attachment_ids` 替代 `repository_url`。两者不能同时出现，且不能提交 `connection_config_id` 或 `authorization_confirmed`。

```json
{
  "source": {
    "kind": "service",
    "connection_config_id": "opaque-connection-id",
    "connection_config_version": 7
  },
  "model_id": "optional-opaque-model-id",
  "thread": 4,
  "country_iso_code": "zh_CN",
  "authorization_confirmed": true
}
```

服务模式不能携带附件、Git URL、端点、Header、Token 或任意 TLS 绕过字段。服务端以 `connection_config_id + connection_config_version` 在同一事务中重新检查可见性、启用状态、该版本测试状态和出站安全策略，并固定该任务可使用的连接版本快照；版本已变更则返回 `409 MCP_CONNECTION_VERSION_CONFLICT`，不静默切换到新版本。

### 5.2 创建、取消与上传的重试契约

所有浏览器非 GET 请求要求 CSRF 防护。`POST /mcp-scans` 必须带 `Idempotency-Key`；该键按“认证主体 + 租户/组织范围 + HTTP 方法 + 规范化路径”作用域保存至少 24 小时。相同键和规范化载荷返回初次创建的同一任务（重复响应为 `200`，带 `Idempotent-Replay: true`）；相同键但不同载荷返回 `409 IDEMPOTENCY_KEY_REUSED`。浏览器只在用户显式请求“查询创建结果 / 重试”时复用同一键，不做后台自动重放。

取消任务使用相同的幂等键规则并返回同一任务的当前取消状态。附件分片使用 `upload_id + chunk_index + 内容摘要` 幂等，内容不一致时冲突；附件合并要求 `Idempotency-Key`。连接配置创建、测试、编辑/启停的重试与条件更新规则以 MCP 连接配置设计为准。

## 6. 校验、错误处理与安全边界

### 6.1 来源校验

- `kind=repository`：恰有一个有效来源（Git URL 或至少一个可用附件）；Git URL 必须满足 §4.2 的协议、URL 组成、DNS 与 Git 出站策略，附件必须属于当前主体/允许范围并通过安全检查；
- `kind=service`：恰有一个可用 `connection_config_id + connection_config_version`，`authorization_confirmed=true`，且没有仓库 URL/附件；创建时以配置版本条件校验，版本变化返回冲突；
- `model_id` 必须对当前主体可见；`thread` 必须落在服务端允许范围；
- 服务端覆盖或校验输出语言为 `zh_CN`，不接受用户构造的其他语言值。

### 6.2 用户可见错误

| 情况 | 页面行为 |
| --- | --- |
| 无可选连接 | 说明原因并提供 MCP 连接配置入口；不提供临时端点输入。 |
| 配置在选择后停用、未测试、版本改变或失去权限 | 创建被拒绝；版本改变返回明确冲突，保留页面并要求刷新后重新选择。 |
| 附件上传/校验未完成 | 禁止创建，明确显示待完成项。 |
| Git URL 不合法或来源互斥冲突 | 在来源区就地提示，服务端创建接口同样拒绝。 |
| 模型无权限或并发不合法 | 保留其他输入，提示刷新受治理选项。 |
| 创建请求超时/网络结果不确定 | 按幂等键查询或由用户明确重试，不自动发起第二个创建请求。 |

### 6.3 数据最小化与审计

- MCP 工作台、任务列表/新建/详情、可选连接、报告和错误消息只读取白名单安全字段；
- 在上述任务相关接口中，连接端点、Token、Header（含名称和值）、Cookie、证书、原始测试响应、附件内部内容和密钥不得进入浏览器响应、日志、报告或审计文本；
- 配置管理详情 `GET /mcp-connection-configs/:id` 是受权限控制的最小例外：仅配置管理者可读取 `server_url`、Header 名称及“secret 已配置”状态，绝不返回任何 secret 值；源代码附件首期不提供浏览器下载接口；
- 服务端记录来源类别、连接配置 opaque ID/版本、安全授权声明、模型 ID、并发与创建主体，便于审计；
- 授权确认只说明用户确认具备测试授权，不替代平台对连接配置、访问范围与出站策略的校验。

### 6.4 权限、资源可见性与条件更新

| 主体 | MCP 任务/附件 | MCP 连接配置 |
| --- | --- | --- |
| 普通用户 | 可在获授范围查看工作台与任务；可创建任务、上传自己的附件；只可取消自己创建且仍可取消的任务 | 只能管理自己拥有或被授予管理权的配置；可创建、编辑、测试、启停该范围配置 |
| 安全审计员 | 仅可查看获授任务及报告的安全摘要；不可创建、上传、取消 | 仅在策略允许时读取列表级安全摘要；不可读取详情、创建、编辑、测试或启停 |
| 管理员 | 按组织策略查看、创建、取消和治理组织范围任务 | 按组织策略管理组织范围配置 |

对不可见的任务、附件和配置返回 `404`；对已知但由角色禁止的写操作返回 `403`。所有写请求执行 CSRF 校验；配置编辑/启停还需 `If-Match` 或等价期望版本，避免丢失更新。

## 7. 非目标

- 不把 MCP 任务页改造成通用任务创建页；
- 不在任务页增加 Token、Header、Cookie、端点、跳过 TLS 校验、上传 CA 或 mTLS 客户端证书；
- 不让模型配置替代 MCP 连接配置，或把两者合并为一种配置 schema；
- 不在本期处理私有 Git 凭据、OAuth、代理、资产台账或跨域风险聚合；
- 不在 MCP 工作台显示 AI 基础设施、模型红队、Agent 等其他业务域的任务和风险。

## 8. 验收标准

1. 从 `/tasks/mcp` 点击主操作能进入 `/tasks/mcp/new`，页面主体全程保持 MCP 专属文案、路由和接口；
2. 新建页无任务类型切换器、无语言选择器，且输出固定为中文；
3. 代码/仓库与服务扫描的来源字段严格互斥，客户端和服务端都能阻止无效组合；
4. 服务扫描只能选择测试成功、启用且有权限的 MCP 连接配置，任务页永不输入或回显连接 secret；
5. 无可用连接时只引导到凭证配置，不降级为自由端点/Token 输入；
6. 任务创建、详情、取消和附件均使用 MCP 专属 API，非 MCP 任务 ID 不可被 MCP 详情接口读取；
7. 成功创建跳到 MCP 专属详情；重复点击、网络不确定和配置状态变化不会产生不可控的重复任务；
8. 工作台指标、近期任务和风险发现均局限于 MCP 任务，且空态、无权限、局部失败可被用户辨别；
9. 旧 MCP 创建路由会跳转到新路由；通用任务接口对 MCP 类型明确拒绝，新 MCP 专属详情仍可读取历史 MCP 任务；
10. Git 来源和连接服务均经过相应的出站/版本/权限校验，配置管理详情的最小可见例外不会扩散到任务相关接口。
