# Agent 配置维护工作台设计

**日期：** 2026-08-31
**状态：** 设计审阅中
**方向：** A · 配置维护优先

## 目标与范围

把“Agent 配置”从目录、模板、原文编辑和受控测试混排的页面，整理为一个面向管理员日常维护的工作台：先查看安全的配置目录，再针对一个已选配置或一次新建操作进入本地工作区。

本包只调整 `web/console` 的 Agent 配置界面、对应前端测试与必要的设计文档。它不增加 Agent API、服务端权限、配置格式、Provider 能力、持续健康检查、风险评分、历史记录、审批或版本回滚。管理员“加载模板”指前端只为管理员启用模板查询与创建工作流，不改变既有模板路由的兼容授权语义。

## 设计原则

1. **目录优先，原文按需。** 页面首屏只能呈现安全的名称、数量和权限语义；配置原文、密码字段、测试 Prompt 与测试输出只在已选工作区的本地状态中存在。
2. **管理维护优先。** 管理员应先知道有哪些可见配置、当前正在维护哪一项、下一步可执行什么动作；不会把创建流程或单次测试误塑造成系统全局健康看板。
3. **受控操作有清晰边界。** 编辑/保存/删除与连接/Prompt 测试分区呈现。所有写操作沿用既有确认、CSRF、审计、取消和固定安全反馈机制。
4. **缓存不等于当前可见性。** 目录请求只有处于成功状态时才可驱动目录摘要、数量、台账和目录派生标签。重取变为无权或失败后，不能继续显示旧缓存。
5. **不虚构后端事实。** 目录数量是当前可见的完整未分页目录数量；连通性与 Prompt 结果只描述一次受控请求的结果，不声称持续可用、SLA 或风险等级。

## 信息架构与视觉层级

### 1. 页面头与安全目录概览

保留页面头“Agent 配置”和管理员的“新增 Agent 配置”入口。说明文案强调“浏览受身份范围控制的 Agent Provider 配置；管理员可在受控工作区维护并执行一次测试”。

当 `namesQuery` 成功时，页面头下方显示纯展示的 `AgentConfigurationBrief`：

- 当前可见配置数量，例如“当前目录 12 项”；
- 当前角色的能力表述：“可查看原文”或“可维护与验证”；
- 使用提示：“选择一项后在本地工作区查看或维护原文”。

该组件只接收计数、角色能力和静态文案；它没有名称数组、原文、模板字段、密钥、Prompt 或测试输出的 props，也不访问 TanStack Query。

### 2. 配置目录

紧随概览的是完整未分页的“配置目录”。保留现有表格可访问性语义，但把动作从模糊的“查看”改为明确的“进入工作区”。每行只显示：

- 配置名称；
- 访问模式：“受身份范围控制”；
- 当前选中状态或“进入工作区”操作。

不显示 Provider 连通性、最后测试时间、凭据是否存在等未由安全 DTO 提供的事实。选中行以雾灰填充和低对比强调色标记，不依赖红/绿状态色。

### 3. 受控配置工作区

选择已有配置或点击“新增 Agent 配置”后，目录下方出现工作区；关闭后清空本地敏感状态并回到目录。

工作区由三个边界清晰的区域组成：

1. **工作区标题。** 显示配置名称、创建/既有配置语义和“原文仅在当前本地工作区显示”的说明，以及关闭动作。
2. **配置来源与原文。**
   - 已有配置：单独加载并显示 YAML 原文；普通用户和审计员保持只读，管理员可编辑。
   - 新建配置：管理员先选择 Provider 模板，填写受控必填字段；高级可选字段继续收在“高级设置”中，并保留下载配置模板。模板仍在加载时显示工作区内加载态；加载失败显示固定错误与重试；成功但没有可用模板时显示空态。上述三种非就绪状态只保留关闭/重试，不显示原文编辑器或任何写入、删除、测试动作。结构化字段生成原文预览，但原文编辑器仍是最终提交内容。
3. **操作与验证。**
   - “配置操作”：保存（需要现有确认弹窗）和删除（需要现有确认弹窗）；只对管理员可见。
   - “受控验证”：连通性测试和 Prompt 测试。Prompt 输入、显式允许的输出、加载状态和固定结果都被限制在本工作区；旁注明确“单次测试不代表持续健康”。只对管理员可见。

全局页面不再把某个工作区的测试结果放在目录前面。工作区内部可以使用固定的成功/失败消息条，保证结果与触发它的动作相邻。

### 4. 窄屏行为

在约 960px 以下，目录保持在工作区前方，工作区内部从双区/双栏收为单列：原文在前，配置操作与受控验证随后。根容器与工作区使用 `minWidth: 0`；如表格需要横向空间，只允许表格自己的局部视口滚动，不能让整个页面横向溢出。在约 390px 下，按钮正常换行，Prompt 和原文编辑器占满可用宽度。

## 数据流、权限与生命周期

### 目录与缓存

`fetchAgentNames` 继续是完整目录的唯一来源。页面需派生 `const catalog = namesQuery.isSuccess ? namesQuery.data : null`，并只从 `catalog` 渲染：目录概览、目录计数、空态和配置台账。

因此当已有缓存随后重取为 `403` 或通用错误时，页面只显示相应 `StatePanel`，不会遗留旧的目录摘要、数量、行、选中名称标签或新建入口的目录语义。已有的本地工作区不使用目录缓存恢复原文，也不会发起新的原文读取；它保留到用户显式关闭、切换或其既有生命周期清理逻辑执行为止。

### 原文、模板与测试内容

- `fetchAgentConfig(name)` 仍在选择后按需调用，结果仅写入 `AgentConfigPage` 的本地 `content`；绝不改成 query，也不作为目录行或概览输入。
- 模板请求继续只在管理员身份启用。模板中的密码字段应保持密码输入控件，且模板值不流入目录或概览。
- Prompt 和显式测试输出继续只在当前工作区本地状态中短暂存在。成功响应仅显示 API 合约明确允许且长度受限的输出；缺失或异常内容仍用固定安全文案。
- 切换配置、关闭工作区、卸载页面、操作失败和已存在的失效流程继续中止相关请求、递增 epoch、清空原文/模板值/Prompt/结果、把结构校验复位为无效，并释放互斥状态。操作失败后不得让旧 `valid` 继续启用保存、连接或 Prompt 测试。

### 工作区就绪门槛

已有配置在 `configState === 'ready'` 前，工作区只显示原文加载或固定失败重试态以及关闭动作；保存、删除、连通性测试、Prompt 输入和 Prompt 测试都不渲染，也不能由内部 action 函数绕过该门槛。开始加载、切换配置和原文加载失败时必须立即把结构校验状态复位为无效，避免旧配置遗留的 `valid` 状态用于空内容或新配置。

新建配置只有在管理员模板查询成功、至少有一个模板、已选模板和生成的原文均处于可校验状态时才进入可操作状态。模板加载、失败或空态同样不能提交、删除、连接或测试。提交中的互斥、AbortController 与 epoch 行为继续优先于所有局部操作。

### 角色与受控写入

`user`、`auditor`、`admin` 保持可读；前端只向 `admin` 展示并启用创建、编辑、保存、删除、模板工作流、连接测试和 Prompt 测试。保存、删除、连接和 Prompt 测试继续复用当前 API、CSRF 和服务端审计边界，模板路由本身不因本包改变。前端不显示 Provider 原始错误、路径、诊断或未许可的原始响应。

## 状态与错误体验

目录层保持四种独立状态：加载、无权、失败（可重试）、空目录。选中配置的原文加载在工作区内拥有自己的加载/失败/重试状态，不能与目录失败混淆。

所有动作失败使用固定的中文安全反馈，如“Agent 配置保存失败，请显式重试。”或“Agent 测试失败，请显式重试。”；不得直接渲染服务端 `message`、文件路径或 Provider 诊断。保存/删除成功后沿用现有清空工作区和失效目录查询的行为。连接或 Prompt 测试成功只说明此次受控操作完成，不扩展为全局运行结论。

## 可访问性

- 目录概览以命名 `region` 暴露，数量和权限语义使用可读文本；
- “进入工作区”、保存、删除、测试和关闭的按钮具有明确名称；
- 选中目录项通过可见样式与文本语义共同表达，不能只依赖色彩；
- 状态/错误使用现有 `StatePanel`、`MessageBar` 的适当 `role`；
- 提示与禁用逻辑仍基于原文结构校验、配置名称约束和提交中状态。

## 验收与测试合同

### 组件合同

为 `AgentConfigurationBrief` 建立纯展示单元测试：

1. 完整目录显示准确“当前目录 N 项”和管理员/只读能力边界；
2. 空目录显示 0 项而不包含任何虚构风险或健康措辞；
3. 接口不接收、DOM 也不输出原文、凭据、Prompt 或测试输出哨兵值。

### 页面集成合同

在 Agent 页面测试中覆盖：

1. 管理员看得到概览、新建入口、进入工作区后的保存/删除/两类测试；普通用户和审计员保持只读；
2. 选中已有配置时，原文仅存在于本地编辑器，TanStack Query 缓存和目录概览不出现原文/令牌哨兵；
3. 目录先成功、随后重取为 `403` 或 `500` 时，只显示独立安全状态，目录概览和台账消失；已完成加载的本地工作区不以缓存重建目录内容；
4. 新建路径仍提供模板、必填字段、高级设置和下载模板；
5. 已有原文或模板尚未就绪、加载失败或模板为空时，只能重试/关闭；所有写入、删除和测试控制均不可用，切换配置会使旧结构校验失效；
6. 关闭工作区后，原文、模板值、Prompt、测试输出及其哨兵值均不再存在于 DOM 或查询缓存；
7. 保存/删除确认、并发互斥、取消/切换时清理、操作失败后使结构校验失效、固定错误和显式受限 Prompt 输出保持已有合同；
8. 结构样式保证根容器、工作区和局部表格视口的窄屏约束。浏览器验收在已登录会话中检查 960px 与 390px 布局。

### 完成证据

实现完成前至少执行 Agent/知识库相关 Vitest、控制台 lint、`tsc -b`、生产构建；随后在用户登录后的本地预览中检查管理员和只读角色的工作台边界。不会把登录凭据读入或输入自动化。

## 实现边界

预期改动集中在：

- `web/console/src/features/knowledge/AgentConfigPage.tsx`；
- 新增纯展示组件及其测试（命名以 `AgentConfigurationBrief` 为准）；
- Agent/知识库页面测试；
- 如样式分离确有必要，仅增加与此工作台直接相关的前端文件。

不修改 Go/Python 服务、知识库 API 文档或 Swagger，因为路由、请求/响应结构和权限语义均保持不变。
