# 左侧导航：扫描工作区与凭证配置

## 背景

平台的核心操作从泛化的“扫描任务”收敛为四类被测对象：MCP Server、Agent Skill、AI 基础设施和 Agent 工作流。模型红队评测的后端兼容能力保留，但本阶段不向前端用户暴露。

现有任务后端只有 `mcp_scan`、`ai_infra_scan`、`agent_scan` 和隐藏的 `model_redteam_report`。其中 MCP 与 Skill 复用同一个扫描引擎；后续会新增可持久化的扫描对象标识，以便列表、报告和统计单独识别二者。本次只建立导航外壳，不修改任务接口或扫描引擎。

## 已确认的产品决定

1. “扫描任务”应成为可展开的一级工作区，二级项固定为：MCP 扫描、Skills 扫描、AI 基础设施扫描、Agent 工作流扫描。
2. MCP 与 Skills 共享扫描引擎，但后续必须在平台数据中独立识别，不能在任务列表、报告和统计中混为同一类。
3. 模型红队评测不得出现在新的前端导航、扫描入口、筛选项或任务标签中。
4. “模型与凭据”更名为“凭证配置”，二级项为“模型配置”和“智能体配置”。
5. AI 基础设施扫描的核心输入是目标地址与扫描参数，不要求配置模型。

## 本次实现范围：导航第一步

本次交付仅改变左侧导航及其可访问交互，使用户能够看见并进入正确的工作区入口；不改变扫描表单、任务持久化、报告映射或后端 API。

### 扫描任务分组

- 一级文字“扫描任务”继续链接到现有 `/tasks` 全部任务台账。
- 独立的展开按钮负责显示或隐藏二级菜单，使用明确的 `aria-expanded` 与 `aria-controls` 语义；文字链接不承担折叠职责。
- 当前地址位于 `/tasks` 下时，分组自动展开并以组级激活样式提示当前位置。
- 二级入口使用可用的任务创建路由，分别携带仅供后续页面读取的 `scan` 查询参数：
  - `/tasks/new?scan=mcp`
  - `/tasks/new?scan=skills`
  - `/tasks/new?scan=ai-infra`
  - `/tasks/new?scan=agent-workflow`
- 第一阶段不解析该查询参数，因此不会伪造“已完成的独立工作台”；下一阶段会让创建页按该参数预选安全表单并建立 `scan_scope` 持久化设计。

### 凭证配置分组

- 一级文字“凭证配置”链接到现有 `/models` 页面。
- 二级入口为：
  - “模型配置” → `/models`
  - “智能体配置” → `/knowledge/agents`
- 本阶段不删除知识库内部的 Agent 配置入口，也不变更页面标题；这些属于下一阶段的信息架构收敛，避免导航改动与页面迁移混在一次提交中。

### 角色与折叠行为

- 两个分组沿用原有模型与知识库的角色可见性：管理员、普通用户和安全审计员均可见；具体页面仍由既有路由守卫决定读写权限。
- 收起整条侧栏时，不渲染二级条目；一级链接及展开控制仍保持可访问名称，避免窄侧栏产生不可点击的密集菜单。
- 小屏幕保持既有响应式布局；二级菜单以缩进和较小的字级表达层级，不另造悬浮抽屉。

## 不在本次范围内

- 新增 `scan_scope` 数据库字段、API DTO、任务筛选、报告标签或统计。
- 按扫描类型改造任务创建页、目标输入、附件策略、AI 基础设施的无模型表单规则。
- 隐藏模型红队评测的旧创建表单与历史记录。
- 删除知识库页面中的 Agent 配置标签或迁移旧 URL。
- 任何扫描引擎、模型凭证、Agent 配置或权限逻辑变更。

## 验收条件

1. 普通用户侧栏的主级顺序包含“扫描任务”和“凭证配置”，且不再显示“模型与凭据”。
2. 两个分组可独立展开；展开后显示各自精确的二级名称与正确链接。
3. 在 `/tasks`、`/tasks/new` 和其子路径中，“扫描任务”保持展开并反映活动状态；在 `/models` 与 `/knowledge/agents` 中，“凭证配置”保持展开并反映活动状态。
4. 收起侧栏后，一级导航仍有完整无障碍名称，二级链接不会残留为不可见焦点。
5. 现有角色筛选、报告激活状态和路由保护测试继续通过。
