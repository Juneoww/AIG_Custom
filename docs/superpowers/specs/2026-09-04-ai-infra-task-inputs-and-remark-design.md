# AI 基础设施扫描：目标输入与任务备注设计

**状态：** 已与用户确认，待实现  
**分支：** `codex/ai-infra-scan`（基于 `develop`）  
**日期：** 2026-09-04  
**关联设计：** `2026-09-03-ai-infra-scan-design.md`；本文件替代其中“新建 AI 基础设施扫描任务”的表单结构与任务备注边界。

## 1. 目标

优化 AI 基础设施扫描专属新建页的信息架构，并保留可追溯的任务备注。

- 手工填写的扫描目标与上传的目标清单文件是同一类数据的两种录入方式；两者应在同一“扫描对象”步骤并列呈现。
- “任务说明 / 备注”是对本次任务的业务说明，不是扫描目标、附件内容或扫描参数。
- 备注须持久化并在授权任务详情中展示，但绝不参与目标解析、不会传给扫描引擎，也不进入任务列表。

## 2. 现状与问题

现有专属新建页将目标正文放在“第一步：扫描目标”，而通用附件组件被单列为“第三步：附件”。对于 AI 基础设施扫描，服务端会将 `content` 与附件中的 UTF-8 目标表达式合并、校验并去重；因此附件在这里并不是独立业务资料，而是目标批量导入通道。

现有平台任务请求、任务实体与引擎任务均没有独立的备注字段：

- `content` 在 AI 基础设施扫描中会按目标表达式解析，不能承载自然语言备注；
- `params` 是模型、超时和端口模式等扫描配置，且会下发给扫描引擎；
- `attachment_ids` 在该任务类型中会被读取为目标清单；
- 任务详情刻意不返回原始目标、附件或任意未知参数。

因此，复用 `params` 保存备注虽然改动较小，但会污染执行参数、让备注进入引擎下发链路，不满足“任务说明”的语义和最小暴露原则。

## 3. 已确认方案

采用平台侧独立 `remark` 字段。

### 3.1 表单信息架构

专属新建页调整为三步：

1. **扫描对象**
   - “扫描目标”：多行手工录入；仅接受目标表达式，不再使用“扫描目标或任务说明”的混合标签。
   - “导入目标清单（可选）”：与手工录入并列的上传区，上传 UTF-8 目标清单文件；清楚标注每行一个目标、服务端合并校验，以及单个清单最大 1 MiB。
   - 两个目标来源可任选其一或同时使用；至少须有一个来源。手工目标和已上传清单将在服务端合并、校验、展开并去重。
   - “任务说明 / 备注（可选）”：置于扫描对象步骤内的独立字段，不作为目标输入或上传文件。
2. **扫描配置**
   - 选择已在凭证配置中登记且当前可用的受治理扫描模型；
   - 设置超时和端口扫描模式；
   - 语言继续固定为中文，不显示语言选择器。
3. **确认并提交**
   - 明确授权目标范围、幂等提交和网络失败不自动重复创建的行为；
   - 不再存在独立的“附件”步骤。

通用“创建扫描任务”页面的附件行为不在本次改动范围内。

### 3.2 备注的存储与传输边界

新增可选 `remark`，采用下列合同：

| 层级 | 变更 | 边界 |
| --- | --- | --- |
| 浏览器创建请求 | `remark?: string` | 仅专属 AI 基础设施表单写入；去除首尾空白，空值省略。 |
| 平台任务输入与实体 | `Remark string`，持久化为 `platform_tasks.remark` | 有界文本，默认空字符串，旧任务兼容为空。 |
| 任务详情安全 DTO | `remark?: string` | 仅在有内容时向已授权详情页投影；任务列表不新增备注列或字段。 |
| 引擎适配器 / 任务下发 | 不增加字段 | `EngineTask`、WebSocket 任务消息和扫描参数均不带备注。 |
| 审计与报告 | 不写入审计元数据、列表或报告快照 | 避免在广泛可见的数据面重复传播用户自由文本。 |

备注最大长度设为 **2,000 个 Unicode 字符**。后端在创建边界校验长度与 UTF-8 有效性；前端同步提示剩余字符数或最大长度。React 默认文本渲染即可避免将备注作为 HTML 解释。

### 3.3 目标输入规则

- `content` 继续只承载手工目标表达式；允许在已成功上传目标清单后为空。
- 附件仍走现有 opaque ID 上传、所有者隔离、分片上传与创建时绑定流程；AI 基础设施任务创建前，服务端使用现有 `ReadReadyTargetExpressions` 读取并验证清单。
- 前端的即时预览仅显示手工输入可识别的目标数；最终合并后的目标数量由服务端计算，并继续通过详情的安全 `target_count` 摘要展示。
- 任何备注文本都不能影响目标预览、目标数量、端口扫描或引擎输入。

## 4. 后端实现设计

### 4.1 数据库迁移

新增下一版数据库迁移（当前架构版本后的顺序版本）：

- `platform_tasks.remark`：`text NOT NULL DEFAULT ''`；
- 迁移必须幂等，既有记录的备注保持空；
- 运行时架构校验同步要求该列存在；
- 不新增索引，也不修改现有任务唯一键、附件绑定或任务状态迁移。

### 4.2 服务与幂等性

- `CreateInput`、`Task`、`View` 和内存/GORM 仓储链路携带备注；
- 创建服务对备注做长度与 UTF-8 校验；
- 相同幂等键的重试必须包含相同备注，否则与其他创建输入不一致一样返回无效请求；
- `validateInfrastructureTargets` 只接收手工目标与附件 ID，绝不读取备注；
- 构造 `EngineTask` 时不复制备注，从而保证扫描引擎与旧 WebSocket 协议无需改动。

### 4.3 浏览器安全投影

- `TaskDetail` 新增有界的可选 `remark`；
- 只在服务端既有任务授权通过后返回，并且不改变 `TaskSummary` 的窄列表合同；
- 前端解析器拒绝超长或非字符串备注，避免未知响应直接进入页面；
- AI 基础设施专属详情在“任务安全摘要”下新增“任务说明”区块，只有备注非空时展示。

## 5. API、文档与兼容性

本次改变创建请求和详情响应，因此须同步：

- 中文、英文 API 参考文档；
- `internal/apidocs/swagger.yaml`、`swagger.json`、`docs.go`；
- Swagger 同步测试；
- 前端 DTO、解析器和相关任务 API 测试。

旧客户端不发送 `remark` 时保持完全兼容；旧任务读取时不显示备注区块。未改动通用任务创建页面、现有任务列表合同和扫描引擎协议。

## 6. 错误处理与权限

- 目标为空且没有任何已成功上传的清单时，前端阻止提交并给出“请填写扫描目标或导入目标清单”的固定提示；服务端仍是最终校验边界。
- 清单不是 UTF-8、超过 1 MiB、含无效目标或合并后超过既有限额时，保持服务端拒绝；浏览器仅显示固定、可重试的提示，不回显原始内容。
- 备注超长或无效 UTF-8 时，服务端返回无效请求；前端在提交前提供长度约束。
- 备注仅遵循既有任务详情授权范围；审计员的只读能力不改变，取消权限不受影响。

## 7. 验证计划

前端测试至少覆盖：

- 专属新建页只有“扫描对象 / 扫描配置 / 确认并提交”三步；
- 目标手工输入与目标清单上传在同一表单步骤；
- 仅手工目标、仅已上传清单、两者同时存在、两者均缺失的提交行为；
- 备注与目标输入独立，备注不触发目标解析错误；
- 创建请求携带/省略 `remark` 的合同；
- 详情只在备注存在时展示“任务说明”，列表不展示备注。

Go 测试至少覆盖：

- 创建、重试幂等、内存/GORM 读写及迁移兼容；
- 备注不进入 `EngineTask`、任务适配器或审计元数据；
- AI 基础设施目标验证仍只合并 `content` 与附件；
- 浏览器详情 DTO 的有界备注投影，列表 DTO 不变；
- API 与 Swagger 合同同步。

按改动范围执行 `go test ./...`、`go test ./internal/apidocs`、控制台测试/类型检查/lint/生产构建，以及 `git diff --check`。当前环境若仍缺少 Go，则应明确记录未运行的 Go 校验，而不能将其表述为通过。

## 8. 非目标

- 不让备注成为扫描语法、引擎提示词或模型输入；
- 不增加任务列表备注列、搜索维度或批量编辑能力；
- 不修改 MCP、模型红队评测、Agent 扫描的附件语义；
- 不改变凭证配置、模型治理或扫描端口策略。
