## 1. 产品概述

### 1.1 产品定位

AIG Custom Platform 是基于 Tencent Zhuque Lab AI-Infra-Guard 扫描能力构建的单租户企业 AI 安全治理平台。平台面向组织内部安全团队和 AI 应用团队，将 AI 基础设施、MCP Server 与 Agent Skills、智能体工作流及大模型提示词安全检测能力，统一封装为具备身份认证、权限隔离、任务治理、审计追踪、管理层报告和企业品牌能力的产品。

产品采用“企业平台壳层 + 既有扫描引擎”的渐进式架构：

- 企业平台负责账号、角色、会话、任务所有权、模型密钥、附件、审计、品牌和报告；
- 既有 Go/Python 扫描器继续负责检测执行、规则判定和原始结果生成；
- 浏览器只访问受保护的平台 API，不直接信任旧任务接口、身份请求头或 Agent 回调；
- 平台通过受控适配器和内部凭据连接扫描 Agent，逐步收敛旧系统边界。

### 1.2 产品愿景

为单个组织提供可私有化部署、可审计、可追责、可持续演进的 AI 安全检测工作台，使安全团队能够统一发起扫描、管理模型与规则、跟踪风险、导出不可变报告，并让业务用户在清晰的权限边界内完成自助安全检查。

### 1.3 核心价值

1. **统一治理**：将分散的 AI 安全扫描能力统一到账号、角色和审计体系下。
2. **数据隔离**：任务、附件、私有模型和报告按所有者隔离，减少越权和密钥泄露风险。
3. **可信追踪**：关键变更和导出动作形成持久化审计记录，支持故障恢复和事后核查。
4. **结果固化**：任务完成时生成不可变报告快照，历史结论不受后续规则或品牌变更影响。
5. **私有交付**：以 PostgreSQL 与 Docker 为当前交付基线，面向麒麟 Linux、离线环境和多架构部署演进。

## 2. 背景与问题

### 2.1 业务背景

组织在引入大模型、AI 基础设施、MCP 工具和智能体工作流后，需要持续识别组件漏洞、配置风险、越权能力、提示词攻击面和模型安全问题。现有 AI-Infra-Guard 已具备丰富扫描能力，但原始产品形态以扫描执行为中心，不能直接满足企业场景下的账号治理、数据隔离、审计、管理层报告和标准化交付要求。

### 2.2 当前主要问题

| 问题 | 影响 |
| --- | --- |
| 缺少完整企业身份与角色边界 | 无法可靠区分管理员、业务用户和审计人员，也难以限制跨用户访问 |
| 任务与附件缺少平台所有权治理 | 浏览器输入可能绕过受控边界，任务和文件存在越权风险 |
| 模型 Token 等敏感信息治理不足 | 密钥可能进入响应、日志或旧明文存储 |
| 扫描结果缺少不可变管理报告 | 历史结果可能因规则、品牌或展示逻辑变化而产生解释不一致 |
| 关键操作审计不完整 | 无法可靠回答“谁在何时进行了什么变更或导出” |
| 旧嵌入式前端不可维护 | 难以形成独立品牌、角色化导航和现代企业工作台体验 |
| 部署边界不够明确 | 难以满足 PostgreSQL、HTTPS、内部 Agent 凭据、离线和国产化交付要求 |

### 2.3 机会

在不重写扫描引擎和规则体系的前提下，通过平台化治理层快速补齐企业产品能力，可以降低改造风险、保留既有检测积累，并为后续前端、国产化数据库和规模化运营提供稳定边界。

## 3. 产品目标与成功标准

### 3.1 一期目标

- 建立本地账号、强制改密、安全会话和管理员/普通用户/安全审计员三角色体系；
- 建立任务、附件、模型、报告和管理操作的服务端权限边界；
- 将浏览器任务入口迁移到受保护平台 API，并对 Agent 建立内部令牌认证；
- 为可信完成任务自动生成不可变报告快照，提供在线详情、30 天趋势和中文 PDF；
- 建立用户、角色、模型、规则、品牌、报告导出等关键操作的持久化审计；
- 交付可维护的独立品牌企业控制台；
- 形成 PostgreSQL、Docker、麒麟 Linux、多架构和离线部署的发布候选。

### 3.2 产品成功标准

| 维度 | 一期成功标准 |
| --- | --- |
| 身份安全 | 所有平台数据接口均以服务端认证 Subject 授权；伪造用户名或角色请求头无效 |
| 权限隔离 | 普通用户只能访问本人任务、附件、私有模型和报告；审计员可全局只读任务、脱敏报告和审计记录，但默认不可读取原始附件；管理员可治理全局资源 |
| 敏感信息 | 模型密钥加密存储，API、审计、错误和日志不返回明文 Token、原始凭据或私有文件路径 |
| 任务可靠性 | 同一所有者与幂等键只创建一个平台任务；不确定 ACK 不自动重复下发；Agent 事件绑定实际分配关系 |
| 报告一致性 | 每个可信完成任务至多生成一个不可变快照；在线详情和 PDF 使用同一快照 |
| 审计完整性 | 关键治理、状态变化和报告导出具备 pending/completion 或等价持久化审计，可对账恢复 |
| 部署 | PostgreSQL 迁移显式执行，运行时不执行 DDL；生产必须使用 HTTPS 与独立高熵凭据 |
| 交付质量 | 角色、越权、迁移、任务状态、报告、PDF 和 Compose 均有自动化或环境验收证据 |

## 4. 用户与角色

### 4.1 目标用户

#### 系统管理员

负责平台初始化、用户与角色管理、全局模型、规则和知识库治理、品牌设置、异常报告补建及系统运维。管理员需要全局可见性，但不应在页面或 API 中直接看到模型明文密钥。

#### 普通用户

通常为 AI 应用负责人、研发或安全自查人员。用户需要配置本人模型、上传附件、创建扫描、查看本人任务与报告并导出结果，不能查看其他用户的私有资源。

#### 安全审计员

负责组织级安全监督、风险汇总和报告审阅。审计员需要查看全平台任务、脱敏报告和审计记录并导出报告，但不能创建扫描、读取或下载用户原始附件，也不能修改用户、模型、规则、品牌及任务状态。一期不提供审计员附件授权机制。

#### 运维与交付人员

负责部署、迁移、备份、升级、TLS、密钥注入和故障排查。该角色属于组织运维职责，不作为一期应用内第四种业务角色。

### 4.2 角色权限矩阵

| 能力 | 管理员 | 普通用户 | 安全审计员 |
| --- | --- | --- | --- |
| 登录、改密、查看个人信息 | 是 | 是 | 是 |
| 创建扫描任务 | 是 | 是，仅本人 | 否 |
| 查看任务 | 全部 | 仅本人 | 全部，只读 |
| 取消任务 | 全部 | 仅本人 | 否 |
| 上传附件 | 是，归属当前操作者 | 是，仅本人 | 否 |
| 下载原始附件 | 跨所有者仅用于治理且必须审计 | 仅本人 | 否 |
| 管理私有模型 | 可治理元数据 | 仅本人 | 否 |
| 管理全局模型 | 是 | 否 | 否 |
| 查看报告与趋势 | 全部 | 仅本人 | 全部 |
| 导出 PDF | 全部 | 仅本人 | 全部 |
| 补建缺失报告 | 是 | 否 | 否 |
| 用户、角色和密码重置 | 是 | 否 | 否 |
| 规则与知识库变更 | 是 | 否 | 否 |
| 品牌配置 | 是 | 否 | 只读 |
| 查看审计记录 | 全部 | 不纳入一期入口 | 全部，只读 |

## 5. 产品范围

### 5.1 一期范围内

- AI 基础设施漏洞扫描；
- MCP Server 与 Agent Skills 安全扫描；
- Agent 工作流安全扫描；
- Model Redteam/Prompt/Jailbreak 安全评测；
- 本地账号、角色、会话、密码重置与首次改密；
- 受保护任务、附件、模型、规则、品牌和报告 API；
- 全链路关键操作审计；
- 不可变报告快照、趋势、在线详情与 PDF；
- 独立品牌企业控制台；
- PostgreSQL、Docker、麒麟 Linux、`amd64`/`arm64` 与离线交付。

### 5.2 一期不包含

- 多租户、组织树、项目空间或跨组织数据隔离；
- 开放注册、短信/邮件注册、外部客户门户；
- SAML、OIDC、LDAP 或其他企业 SSO；
- 重写扫描规则、检测算法、Python 扫描器或既有结果判定；
- 自动修复漏洞、工单闭环或第三方 SOAR/SIEM 深度集成；
- 已进入引擎的失败任务自动重跑；
- 将旧浏览器任务 API 继续作为公开兼容接口；
- 审计员原始附件访问授权、跨用户附件分享或外部下载链接；
- 达梦数据库驱动、镜像和联合验收；
- 微服务拆分、Redis、消息队列或独立前端常驻服务。

## 6. 核心用户流程

### 6.1 平台初始化

1. 运维配置 PostgreSQL、模型主密钥、Agent 内部令牌和 HTTPS 入口；
2. 一次性 `migrate` 服务将 schema 升级至当前版本；
3. 运维通过本地 CLI 创建首个管理员；
4. 管理员首次登录后必须修改初始密码；
5. 管理员创建普通用户和安全审计员并分配角色；
6. 所有步骤产生必要的运维或应用审计证据。

### 6.2 普通用户发起扫描

1. 用户登录并完成首次改密；
2. 用户选择本人私有模型或管理员提供的全局模型；
3. 如有需要，用户通过受保护接口上传附件并获得 opaque 附件 ID；
4. 用户选择扫描类型、填写目标或内容并提交任务；
5. 平台先持久化任务、所有者和幂等键，再由受控适配器分发；
6. 页面通过受保护任务详情接口短轮询状态，不连接旧 Agent WebSocket；
7. 任务完成后，平台从可信引擎结果生成不可变报告；
8. 用户查看在线报告，必要时导出 PDF。

### 6.3 审计员审阅全局风险

1. 审计员登录后进入安全总览；
2. 查看全平台任务、报告、风险趋势和审计记录；
3. 打开任一报告的安全详情，查看评分、风险分布和技术发现；
4. 导出不可变 PDF；
5. 页面不提供创建、编辑、删除、补建或配置入口，服务端同时执行只读授权。

### 6.4 管理员治理

1. 管理员创建/禁用用户、修改角色或发起密码重置；
2. 管理全局模型、规则、知识库与品牌；
3. 查看所有任务和报告；
4. 对可信已完成但快照缺失的任务执行受审计补建；
5. 审核关键操作审计和恢复状态，处理异常交付或运行问题。

## 8. 报告产品结构

报告以管理层摘要优先，同时支持技术人员下钻：

1. 报告标题、产品品牌、任务类型、完成时间和生成时间；
2. 安全评分和评分说明；
3. 最近 30 个 UTC 自然日的风险趋势；
4. 高、中、低风险分布；
5. Top 风险与优先处置建议；
6. 扫描覆盖范围、任务元数据和总体结论；
7. 技术发现列表，包括标题、证据、影响和修复建议；
8. PDF 页眉、页脚、Logo 和水印。

报告不向浏览器暴露以下内容：

- 原始引擎结果；
- 模型 Token、API Key、Cookie、JWT 或其他凭据；
- Prompt 原文、完整会话、模型完整输出或内部附件；
- 本机绝对路径、内部存储路径和 URL 查询参数；
- 当前可变品牌对象或管理员 ID；
- 未经白名单解析的任意 JSON 子树。

审计员通过上述脱敏报告完成组织级审阅；报告接口不得成为读取任务原始附件或绕过附件权限的入口。

## 9. 数据与生命周期

### 9.1 主要业务对象

| 对象 | 生命周期与约束 |
| --- | --- |
| 用户 | 管理员创建；可禁用；角色互斥；密码和会话独立管理 |
| 会话 | 登录签发；退出、禁用、改密或安全动作可撤销/轮换 |
| 模型 | 全局或私有；Token 加密；禁用后不得用于新任务 |
| 附件 | owner 私有；上传完成后方可绑定任务；以 opaque ID 暴露 |
| 平台任务 | 先持久化后分发；状态单向合法收敛；失败不删除 |
| 报告快照 | 可信任务成功时创建；按 task ID 唯一；创建后只读 |
| 品牌配置 | 当前可变单例；更新只影响未来快照 |
| 审计事件 | 追加式记录；完成投递失败进入可恢复 outbox |

### 9.2 保留与删除

一期不提供普通用户硬删除历史任务、报告或审计记录的产品能力。具体保留期限、归档策略和合规删除流程由交付组织在发布前确定，并作为部署策略补充；在策略确定前，系统应优先保留历史证据，避免静默丢失。

### 9.3 数据库

- 当前仅支持 PostgreSQL 16.x 交付基线；
- schema 通过显式版本化迁移演进；
- 运行账号不需要 DDL 权限，启动只进行只读 schema 校验；
- 升级前必须备份数据库和上传目录；
- 达梦适配属于后续独立项目，不在本期实现中预埋未经验证的驱动或 SQL。

## 10. 安全与隐私要求

### 10.1 信任边界

- 浏览器身份仅来自安全会话，不信任客户端身份请求头；
- Agent WebSocket 和制品传输使用独立 `AIG_AGENT_TOKEN`，不能复用数据库密码或模型主密钥；
- 浏览器不得提交原始引擎结果、扫描完成事件或明文模型凭据；
- 平台端口在生产环境必须位于组织 HTTPS Ingress/反向代理之后；
- 仅受信代理可通过 `X-Forwarded-Proto: https` 建立 HTTPS 语义。

### 10.2 密钥与凭据

- 数据库密码、模型主密钥、Agent Token 和会话令牌必须分别生成；
- 生产密钥通过环境或 Secret 管理设施注入，不写入 Compose、日志或版本库；
- 模型主密钥必须支持 key ID 和历史密钥轮换；
- 错误信息、审计 metadata、报告 RenderModel 和日志必须执行敏感字段及自由文本脱敏。

### 10.3 文件安全

- 禁止目录穿越、公开静态上传目录和浏览器提供磁盘路径；
- 分片名称、存储名和合并目标由服务端生成和校验；
- 文件大小在流式读取期间限制，不能仅信任请求声明；
- 内部制品操作必须绑定精确任务和当前状态。

## 11. 非功能需求

### 11.1 可用性与一致性

- 任务分发、状态回写、报告生成和审计在重试、超时、断连和重启后应可解释并可恢复；
- 不确定网络 ACK 进入显式状态，不以自动重发掩盖不确定性；
- 报告快照和历史审计不可因当前品牌、规则或 UI 更新而改变；
- 恢复任务采用有界批次和超时，不能每轮全表无限扫描。

### 11.2 性能与容量边界

- 列表 API 必须分页；报告列表默认每页 20、最大 100；
- 趋势在服务端计算，不要求浏览器下载全部报告；
- 技术发现最多展示 50 条，并限制单字段和总文本大小；
- 默认附件总大小 50 MiB、单分片 5 MiB；
- 一期正式并发量、任务吞吐、PDF P95 和数据保留容量须在发布候选环境完成基准测试后确定，不在本 PRD 中虚构容量承诺。

### 11.3 兼容性

- 服务端与 Agent 支持 `linux/amd64` 和 `linux/arm64` 交付目标；
- 生产目标为麒麟 Linux + Docker Engine/Compose + PostgreSQL；
- 中文报告字体随镜像嵌入，不依赖宿主字体或公网资源；
- 浏览器支持范围在前端实施阶段确定，至少覆盖组织当前受管的主流 Chromium 浏览器。

### 11.4 可维护性

- 前后端均保留可测试源码，禁止继续以不可维护的静态构建产物作为最终 UI 来源；
- API 的 YAML、JSON 和 Go 内嵌 Swagger 必须保持同步；
- API、任务结构或部署变化必须同步中英文文档；
- 字体和第三方依赖许可材料随镜像和 Release 包分发。

### 11.5 可观测性

- 日志只记录必要标识、状态和动作，不记录任务完整 payload、Token、原始结果或路径；
- 健康检查覆盖平台进程、PostgreSQL 就绪和一次性迁移结果；
- 关键恢复队列和失败状态应能通过审计或管理接口定位。

## 13. 验收标准

### 13.1 身份与角色

- 首个管理员只能通过本地初始化命令创建；
- 首次登录必须改密，改密前业务 API 返回拒绝；
- 匿名、伪造身份请求头、跨所有者和错误角色请求均按预期拒绝；
- 审计员执行 GET 不产生业务写入；
- 禁用用户后现有会话失效。

### 13.2 任务与附件

- 相同幂等键并发提交只分发一次；
- Agent 缺少或使用错误 Token 时无法连接；
- 重复 Agent ID 不抢占当前有效连接；
- 非分配 Agent 无法注入事件或结果；
- Agent 失联后任务进入可解释失败状态；
- 普通用户跨所有者附件引用、下载和任务绑定全部失败；
- 审计员下载任意用户原始附件均返回拒绝，且不存在 Cookie、请求头或角色旁路；
- 管理员仅能为治理目的跨所有者下载，成功与失败均留下不含路径、文件内容和令牌的持久化审计；
- 旧浏览器任务路由在通过正常安全门后返回 `410 Gone`，不能成为回退入口。

### 13.3 报告与品牌

- 真实四类引擎结果生成正确风险计数、评分和技术发现；
- 同一任务并发恢复只产生一个快照和一致成功审计；
- 列表、详情和 PDF 不包含敏感哨兵、原始结果或路径；
- 品牌更新后，旧报告在线详情和 PDF 保持原品牌；
- PDF 可被标准工具打开，中文可提取，字体已嵌入并支持多页；
- 导出成功与失败均留下持久化审计状态。

### 13.4 部署与升级

- 全新数据库和从上一版本升级均可迁移至当前 schema；
- 重复执行迁移幂等；
- 运行账号无 DDL 权限时平台仍可启动；
- schema 缺失关键表、列或唯一索引时平台拒绝启动且不自动修复；
- Compose 仅包含预期服务，迁移器成功后平台和 Agent 才启动；
- 生产未配置 Agent Token、模型主密钥或数据库凭据时必须失败关闭；
- 在 `amd64` 与 `arm64` 目标完成镜像构建、离线导入和麒麟环境冒烟。

### 13.5 控制台

- 三角色看到正确菜单、数据范围和操作按钮；
- 完成登录、改密、任务、报告、模型、审计和品牌核心 E2E；
- 浏览器不连接旧 Agent WebSocket，不调用旧任务 API；
- 会话令牌不进入 localStorage；
- 前端生产构建由 Docker 完成并可嵌入 Go 服务；
- About 页面保留上游归属，默认品牌不复用上游 Logo。

## 15. 风险、依赖与应对

| 风险/依赖 | 影响 | 应对 |
| --- | --- | --- |
| 旧嵌入式 UI 与新平台 API 不一致 | 后端能力无法完整展示，用户可能误判已交付范围 | 将旧 UI 明确标为过渡演示；Task 7–9 交付后才进行最终 UI 验收 |

| 麒麟与 arm64 环境差异 | 发布镜像在目标环境不可用 | Buildx 多架构构建并在真实主机或等价 CI 做离线导入冒烟 |

| 容量目标尚未基准化 | 无法承诺大规模并发和 SLA | 在发布候选环境采集数据后形成独立容量与 SLO 文档 |

## 16. 待确认产品决策

以下事项不阻塞当前后端基线，但必须在对应里程碑开始前确认：

1. 正式产品名称、默认 Logo、品牌文案和 About 页面表达；
2. 一期受支持浏览器版本；
3. 生产任务并发、报告导出时延和数据规模 SLO；
4. 任务、附件、报告和审计的保留期限及合规删除流程；
5. 麒麟验收发行版、版本和 `amd64`/`arm64` 实机清单；
6. 离线环境允许的模型、规则更新和第三方地址接入方式；
7. 达梦适配的目标版本、驱动、授权和供应商测试环境。

## 17. 版本与变更管理

- 本 PRD 是一期产品范围的上位基线；新增范围必须说明业务价值、角色影响、数据影响、安全影响和验收标准；
- 需求变更后应同步更新设计文档、实施计划、API/Swagger、测试和部署文档；
- “已交付”必须有代码、自动化测试或环境验收证据，不能仅以接口声明或页面占位判断；
- 未完成的 UI、国产化和发布任务不得因后端 API 已存在而提前标记为产品完成；
- 重大安全边界变化须重新进行权限、审计、密钥和跨所有者访问审查。

## 19. 术语表

| 术语 | 说明 |
| --- | --- |
| Subject | 服务端根据会话建立的认证主体，包含用户 ID、用户名和角色 |
| Owner | 任务、附件、私有模型或报告所属用户 |
| Engine Adapter | 平台与既有扫描任务系统之间的受控适配边界 |
| Agent | 通过内部令牌认证、执行扫描任务并回传事件的受控进程 |
| Idempotency-Key | 防止同一用户重复创建和分发同一请求的幂等标识 |
| dispatch_unknown | 任务可能已下发但网络 ACK 无法可信确认的显式状态 |
| Report Snapshot | 任务完成时生成、之后不可变的报告数据与品牌快照 |
| RenderModel | 在线报告和 PDF 共同消费的脱敏、版本化报告展示模型 |
| Outbox | 业务提交后可恢复投递审计 completion 的持久化队列 |
| CSRF | 防止浏览器跨站伪造状态变更请求的保护机制 |
