# AI 基础设施端口扫描模式改造说明

> **交付状态：** 端口扫描模式功能已合入 `main`（功能合并提交：`e3faf32d`）。
> **适用范围：** AI 基础设施 / Web 扫描任务。

## 1. 改造目的

本次改造将裸 IP 的端口发现能力明确为可选择、可审计、可在报告中追溯的两种固定模式。用户能够在“常用 AI 服务发现”和“完整 TCP 暴露面发现”之间选择；任务创建、Agent 执行、审计记录、在线报告和 PDF 报告使用同一份可信配置。

端口扫描范围与目标表达式容量是两个独立概念：前者由端口模式决定，后者仍按服务端的目标解析、授权和容量规则处理。

## 2. 用户可见能力

创建 **AI 基础设施 / Web 扫描**任务时，前端必须保留“端口扫描模式”选择。

| 页面选项 | API 值 | TCP 端口范围 | 适用场景 |
| --- | --- | --- | --- |
| 固定 AI 端口（默认） | `fixed_ai` | `11434,1337,7000-9000,18789`，共 2,004 个端口 | 常规 AI 服务发现，优先覆盖常见 AI 服务端口与 7000–9000 区间。 |
| 全量 TCP | `full_tcp` | `1-65535`，共 65,535 个端口 | 已确认授权范围、维护窗口和网络承载能力后的完整 TCP 暴露面发现。 |

`port_scan_mode` 省略时按 `fixed_ai` 处理。当前只支持这两种固定 TCP 模式；不提供自定义端口表达式、UDP 扫描或服务版本识别。

### 2.1 端口发现的目标边界

端口发现仅针对**裸 IPv4**目标，例如 `192.168.10.2`。开放端口随后进入既有 Web、组件指纹与漏洞识别流程。

以下目标不额外进行端口发现，继续走原有 Web 扫描路径：

- URL，例如 `https://ai.example.com`；
- 域名，例如 `ai.example.com`；
- 带端口的 IP，例如 `192.168.10.2:8080`；
- IPv6 目标。

### 2.2 可一次粘贴的扫描目标

AI 基础设施扫描按“一行一个表达式”处理，可以一次性粘贴多行，支持：

```text
192.168.10.2-192.168.10.10
104.147.75.1-104.147.75.10
22.2.10.*
22.2.*.*
192.168.10.0/24
```

范围必须使用标准连字符 `-`；`104.147.75.1\\~104.147.75.10` 会被拒绝。平台合并正文与已就绪附件中的目标、稳定去重后在服务端再次校验。

## 3. 执行与可信数据流

```text
用户在控制台选择模式并提交任务
        ↓
服务端规范化并持久化 port_scan_mode
        ↓
Agent 只使用持久化后的规范化值
        ↓
裸 IPv4 按 fixed_ai 或 full_tcp 做 TCP 端口发现
        ↓
开放服务进入既有 Web、指纹与漏洞识别
        ↓
任务、审计、报告和 PDF 展示可信模式与端口范围
```

这条链路防止前端提示、实际执行和报告内容因原始或未经验证的参数发生不一致。

## 4. API 约定与兼容性

AI 基础设施任务创建请求可以携带：

```json
{
  "task_type": "ai_infra_scan",
  "content": "192.168.10.2-192.168.10.10",
  "params": {
    "port_scan_mode": "full_tcp"
  }
}
```

- `port_scan_mode` 仅接受 `fixed_ai` 或 `full_tcp`；其他值、显式 `null`、空字符串和重复 JSON 键会被拒绝。
- 省略该字段与显式 `fixed_ai` 语义一致。
- 执行端、审计端和报告端只从持久化的规范化任务参数派生模式与端口范围，不信任 Agent 回传的同名字段。
- 非 AI 基础设施任务不会使用或展示端口扫描模式。
- 既有 AI 基础设施任务若没有该字段，按默认固定 AI 端口模式解释。

完整字段见 [API 参考（中文）](../api/reference.md) 与 [API reference (English)](../api/reference.en.md)。

## 5. 报告与审计

任务详情、审计记录、HTML 报告与 PDF 报告会显示实际执行的端口模式和对应范围。展示层只接受以下精确组合：

| 模式 | 端口范围 |
| --- | --- |
| `fixed_ai` | `11434,1337,7000-9000,18789` |
| `full_tcp` | `1-65535` |

未知模式、范围与模式不匹配、非 AI 基础设施任务中的字段，以及重复键等不可信数据不会出现在报告中。

## 6. 安全与运维边界

全量 TCP 模式扫描 65,535 个端口，不设置额外的端口上限。这是平台明确提供的能力，但会显著增加网络连接数、扫描时间和目标业务压力。执行前应：

1. 确认目标、网段与附件清单均在授权范围内；
2. 评估维护窗口、速率、并发和业务承载能力；
3. 对大量裸 IP 目标分批执行并监控影响；
4. 优先在测试或隔离环境验证。

扫描结果用于风险发现和证据保留，不代表系统绝对安全；应结合人工复核、修复与复测形成闭环。

## 7. 验证情况

功能已完成控制台 lint、类型检查、29 个测试文件共 351 个测试、生产构建和静态资源一致性校验；端口模式、Agent、任务创建/重试/审计/快照、HTML/PDF 报告和 Swagger 一致性均已通过定向测试。

完整 `go test ./...` 在当时环境仍受既有测试前置条件限制：迁移集成测试需要 `AIG_TEST_DB_DSN`，Agent 大数据测试需要 `AIG_AGENT_TOKEN`，指纹预载测试依赖缺失的 `data/fingerprints/anythingllm.yaml`。这些环境问题不影响上述定向验证结论。
