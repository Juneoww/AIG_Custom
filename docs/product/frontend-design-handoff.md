# AIG 平台前端设计交接说明

> **用途：** 供前端产品、UX/UI 设计与研发了解当前平台的已交付功能、页面边界、数据状态与设计优先级。
> **口径：** 以当前已合并的控制台、服务端能力和 API 为准；“部分实现”或“暂不支持”不可设计成已可用功能。

## 1. 产品定位与核心闭环

AIG 是面向企业内网或受控环境的 **AI 安全治理与风险发现平台**。它把“选择资产或模型 → 发起受治理扫描 → 跟踪任务 → 固化报告 → 查看趋势与审计 → 治理模型、规则和用户”组织成一个可追溯闭环。

前端首先帮助用户回答四个问题：

1. 当前有哪些 AI 资产、模型或 MCP 服务需要检查？
2. 我可以发起什么扫描，它现在处于什么状态？
3. 已经发现哪些风险，优先应处理什么？
4. 谁发起、谁修改、按什么规则和配置得出结论？

```text
登录与权限确认
      ↓
选择扫描类型、目标、模型、规则与附件
      ↓
任务调度与 Agent 执行
      ↓
成功任务固化为不可变安全报告
      ↓
报告、趋势、审计与治理闭环
```

## 2. 角色与权限设计

前端以登录会话和服务端角色为准控制导航与操作入口；隐藏按钮不能替代服务端鉴权。

| 角色 | 可见范围 | 可执行操作 | 设计要点 |
| --- | --- | --- | --- |
| 普通用户（`user`） | 自己的任务、附件、私有模型和报告；获授权的全局模型与只读知识库 | 创建/取消自己的任务，管理私有模型，查看和导出有权报告 | 主工作角色，突出“创建扫描”和“我的风险”。 |
| 安全审计员（`auditor`） | 全局任务、报告、趋势、审计摘要和系统同步状态 | 只读审阅、导出有权报告 | 不显示创建任务、用户管理、品牌管理、模型写入；不能下载原始附件。 |
| 系统管理员（`admin`） | 全局治理范围 | 用户、模型、规则、品牌、数据同步、报告补建等治理操作 | 高影响动作需要确认、进度、结果反馈和审计提示。 |

### 不能出现在浏览器中的敏感内容

- 模型 Token、密钥、完整内部存储路径、原始 Agent 会话和原始 Prompt 内容；
- 不属于当前用户的原始附件；安全审计员尤其不得读取或下载；
- Agent 内部 Token、WebSocket 连接信息和未经白名单过滤的原始结果字段。

页面仅应显示服务端提供的脱敏摘要和白名单字段。

## 4. 信息架构与页面清单

├─ 登录 /login
├─ 修改密码 /change-password
└─ 重置密码 /reset-password

登录后的应用壳
├─ 治理总览 /                              （全部角色）
├─ 扫描任务 /tasks                          （全部角色）
│  ├─ 创建扫描任务 /tasks/new                （普通用户、管理员）
│  └─ 任务详情 /tasks/:taskId                （全部角色）
├─ 安全报告 /reports                         （全部角色）
│  └─ 报告详情 /reports/:reportId            （全部角色）
├─ 模型与凭据 /models                        （全部角色，写入受角色控制）
├─ 规则与知识库 /knowledge                   （全部角色，编辑受角色控制）
│  ├─ 指纹规则 / 漏洞规则 / 安全评测集
│  ├─ MCP 插件 / Prompt 集合 / Agent 配置

### 4.1 治理总览

首页用于“先判断风险优先级，再进入任务或报告”，建议固定四个区域：

1. 核心指标：快照平均安全分、高/中/低风险数；
2. 30 日趋势：按 UTC 自然日的风险变化；
3. 高风险待办：任务类型、安全分、高风险数、完成时间、报告入口；
4. 最近任务：任务类型、负责人、状态、更新时间、详情入口。

没有已完成报告、无权限、加载失败都必须使用不同状态，不能显示成同一种“暂无数据”。

### 4.2 任务中心

任务列表支持服务端分页、状态筛选和类型筛选。任务状态应使用以下稳定文案：

| 状态值 | 页面文案 | 设计含义 |
| --- | --- | --- |
| `pending` | 等待调度 | 已创建，尚未分配给 Agent。 |
| `dispatching` | 正在调度 | 正在尝试分配。 |
| `running` | 执行中 | Agent 正在执行。 |
| `succeeded` | 已完成 | 可进入对应报告。 |
| `failed` | 执行失败 | 执行已结束且失败。 |
| `dispatch_failed` | 调度失败 | 未能成功分配。 |
| `dispatch_unknown` | 调度状态待确认 | 不能误展示为失败或成功。 |
| `cancelled` | 已取消 | 任务已终止。 |

任务详情应突出任务类型、状态、负责人、创建/更新时间、参数摘要和附件摘要；仅在可取消状态显示取消按钮。取消的网络确认中断应提示“状态待确认，请刷新”，不能自动重复提交。

### 4.3 创建扫描任务

推荐采用分步表单：

1. 选择扫描类型；
2. 填写目标或任务说明，并按类型展示参数；
3. 选择/上传私有附件；
4. 审阅授权范围和高影响提示后提交。

创建请求具有幂等语义；网络异常时提示“可显式重试，将复用同一创建请求”，而不是让用户反复点击。

| 扫描类型 | 主要参数 | 页面引导 |
| --- | --- | --- |
| MCP 扫描 | 任务说明/目标；可选模型；并发 `thread`（1–1024） | 说明用于 MCP 服务、工具和代码风险，不是端口扫描。 |
| AI 基础设施扫描 | 目标；可选模型；超时 `timeout`（1–86,400 秒）；端口模式 | 提供目标格式预览和全量 TCP 警告。 |
| 模型红队评测 | 任务说明；1–10 个不重复待测模型；裁判模型；样本数 `numPrompts`（1–1,000,000） | 明确区分待测模型与裁判模型。 |
| Agent 扫描 | 任务说明；Agent 配置 ID；裁判模型 ID | 标注为工作流安全评估。 |

### 4.4 AI 基础设施目标与端口模式

目标按一行一个表达式处理，支持一次性粘贴多行。支持 URL、域名、单个 IPv4、IPv4 CIDR、IPv4 闭区间和末尾通配符。

```text
192.168.10.2-192.168.10.10
104.147.75.1-104.147.75.10
22.2.10.*
22.2.*.*
```

客户端应提供实时格式和数量预览，但服务端才是最终校验边界。不得提示支持 IPv6 范围/CIDR/通配符、部分八位组通配符（如 `22.*.10.*`）、端口范围、主机名范围、同一行空格分隔多个目标，以及反斜杠/波浪号范围（如 `104.147.75.1\\~104.147.75.10`）。

端口扫描模式是创建页**必须保留**的控件，并在任务详情和报告中回显实际执行的可信模式：

| 页面选择 | API 值 | TCP 端口范围 | 说明 |
| --- | --- | --- | --- |
| 固定 AI 端口（默认） | `fixed_ai` | `11434,1337,7000-9000,18789`，2,004 个端口 | 常规 AI 服务发现。 |
| 全量 TCP | `full_tcp` | `1-65535`，65,535 个端口 | 平台明确支持全量 TCP；必须显示显著的耗时、网络连接与业务压力警告。 |

端口发现仅适用于**裸 IPv4**；URL、域名、带端口 IP 和 IPv6 不额外进行端口发现。全量 TCP 没有额外端口上限，但不取消目标表达式、授权和服务端容量校验。

## 5. 报告与风险呈现

报告是任务成功时生成的**不可变快照**：在线详情与 PDF 出自同一份固化数据，不能设计成会随当前规则、品牌或任务参数实时变化的页面。

报告详情建议包含：

1. 报告 ID、任务 ID、完成时间、生成时间、快照主色和水印；
2. AI 基础设施任务的可信端口扫描模式；
3. 安全分、评分说明、风险分布和重点风险；
4. 30 日风险趋势；
5. 技术发现、修复建议、覆盖范围与结论；
6. PDF 导出及其加载、失败和重试状态。

报告列表优先显示风险级别/安全分、任务类型、完成时间和详情入口；不展示原始扫描结果、完整附件、Logo 二进制或内部所有者标识。

## 6. 模型、知识库与管理

### 6.1 模型与凭据

模型页是受治理模型目录，不是通用密钥管理器。需表达模型名称、供应商模型、状态、来源与可见范围：

- 普通用户创建私有模型，管理员创建全局模型；
- Token 仅在当前提交中发送给服务端，**绝不回填或展示**；
- 编辑时留空表示保持原 Token；停用后新任务不可选择；删除需二次确认；
- 审计员只读，不显示写入操作。

### 6.2 规则与知识库

分类为指纹规则、漏洞规则、安全评测集、MCP 插件、Prompt 集合和 Agent 配置。建议使用“列表/筛选 → 详情 → 管理员编辑”的架构，并明确读写边界：

| 分类 | 全角色浏览 | 管理员编辑 | 说明 |
| --- | --- | --- | --- |
| 指纹规则 | 是 | 是 | 与组件识别结果相关。 |
| 漏洞规则 | 是 | 中文库可编辑 | 英文数据暂无独立分语言治理入口。 |
| 安全评测集 | 是 | 是 | 供模型红队评测使用。 |
| MCP 插件 | 是 | 是 | 与 MCP 扫描关联。 |
| Prompt 集合 | 是 | 是 | 管理入口仅管理员。 |
| Agent 配置 | 是 | 是 | 为 Agent 扫描选择配置。 |

编辑页必须有保存中、成功、失败、未保存修改提醒和无权限状态。

### 6.3 管理与运维

- 用户管理：管理员创建用户、启停、调整角色、发起密码重置；重置 Token 不返回浏览器。
- 审计日志：审计员与管理员查看脱敏分页摘要，不展示密钥、内部路径或原始敏感元数据。
- 品牌设置：管理员维护产品名、主色、水印和 Logo；仅 PNG/JPEG，前后端均校验大小与像素；变更只影响未来报告。
- 系统信息：审计员和管理员查看同步状态；仅管理员可发起同步。

## 7. 通用交互与视觉要求

每个数据页面必须有独立的加载中、空状态、请求失败、无权限、保存中/提交中、操作成功和可重试失败状态。不能将 403、网络异常、尚无数据与“调度状态待确认”统一成一个空白状态。

视觉优先级建议：

- 高风险待办、执行中任务、全量 TCP 警告应处于高视觉层级；
- 风险颜色要配合文字、图标或数值，不能仅依赖红黄绿；
- 总览与报告用指标卡、趋势与可扫描表格，不直接堆放原始 JSON；
- 创建页用分步表单、示例、上下文帮助与内联校验；
- 删除、同步、取消等高影响动作有确认、进度和结果反馈；
- 时间字段明确 UTC 口径或按统一产品规则转换。

## 8. 暂不应设计成已交付能力的事项

| 事项 | 当前情况 | 设计处理建议 |
| --- | --- | --- |
| 代理层与后端应用分层展示 | 尚未交付 | 不设计代理拓扑或分层识别结果页。 |
| Dify 专项证据聚合与置信度 | 尚未交付 | 不展示虚构的专项评分/置信度控件。 |
| Agent 扫描的全部深度能力 | 部分实现 | 保留基础任务与报告承载，不承诺完整运行时观测。 |
| 英文漏洞库独立治理 | 部分实现 | 不新增独立英文漏洞编辑页。 |
| 越狱规则专用编辑器 | 未提供 | 仅只读呈现已有数据。 |
| 规则数据版本追踪 | 未建立持久规则版本 | 不将应用版本误标为规则版本。 |
| 自定义端口、UDP、服务版本扫描 | 未支持 | 不提供自定义端口、UDP 或服务版本识别开关。 |

## 9. 设计优先级

| 优先级 | 设计包 | 原因 |
| --- | --- | --- |
| P0 | 登录/会话、应用壳、治理总览、任务列表/创建/详情、报告列表/详情/PDF | 构成“发现风险 → 查看结论”的最短闭环。 |
| P1 | AI 基础设施目标输入、端口模式警告、模型与凭据、附件交互、知识库浏览 | 直接影响扫描可用性与任务正确性。 |
| P2 | 用户管理、审计、品牌、系统同步、知识库编辑 | 属于治理深度功能，依赖 P0/P1 的统一组件与权限模式。 |

## 10. 前端交付前核对清单

- [ ] 按角色设计导航和操作权限，不为无权限角色保留可点击入口；
- [ ] 为四种扫描类型分别设计参数区域；
- [ ] AI 基础设施扫描保留端口模式，默认固定 AI 端口，并对全量 TCP 给出显著警告；
- [ ] 区分任务状态、空状态、403、网络失败和调度待确认；
- [ ] 报告以不可变快照为中心，在线页与 PDF 信息层级一致；
- [ ] Token、原始附件和内部路径不进入页面、日志、下载文件名或错误提示；
- [ ] 高影响操作有确认、进度、成功和失败反馈；
- [ ] 仅围绕已受支持的后端接口设计写操作，不做无后端支撑的占位功能。
