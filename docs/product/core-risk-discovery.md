# 平台核心风险发现能力

本文说明 AIG 平台当前最核心的四项风险发现能力，以及它们适合解决的问题、输入和输出。

| 功能 | 主要解决什么问题 | 输入 | 结果 |
| --- | --- | --- | --- |
| AI 基础设施 / Web 扫描 | 目标 AI 服务暴露了什么组件、版本和已知风险 | 已获授权的 URL、IP、服务地址、IPv4 CIDR、IPv4 范围或末尾通配符 | 识别出的组件、版本证据、关联漏洞/风险及修复建议 |
| MCP Server 扫描 | MCP 服务、工具定义和代码是否存在危险能力或安全缺陷 | MCP 服务代码、仓库或受控运行目标 | 高风险工具行为、可疑代码/配置、权限与数据泄露风险 |
| 提示词与模型红队评测 | 模型是否容易被越狱、提示词注入或诱导输出不安全内容 | 已治理的模型配置、评测规则和攻击样本 | 攻击成功情况、风险类别、命中证据与评测结论 |
| 组件指纹与版本识别 | 不知道目标具体部署了什么 AI 组件、是否存在已知版本漏洞 | Web 服务响应、HTTP Header、页面内容、图标等 | 组件名称、精确或范围版本、识别证据；为漏洞匹配提供基础 |

## 四项能力的关系

- **组件指纹与版本识别**是底座：先弄清“这是什么、什么版本”。
- **AI 基础设施 / Web 扫描**是面向运行中服务的整体体检：组件识别后，结合漏洞与暴露面给出风险。
- **MCP Server 扫描**专门检查 MCP 的工具、代码和运行行为：重点关注危险工具调用、敏感数据外泄、工具投毒、命令或文件相关风险。
- **提示词与模型红队评测**不扫描服务器漏洞，而是模拟攻击者和模型交互：验证模型在越狱、注入、敏感信息诱导等场景下的防护效果。

## 推荐使用顺序

1. 先对外部或内网的 AI 服务做 Web / 基础设施扫描。
2. 对接入的 MCP Server 做专项扫描。
3. 对实际使用的模型做红队评测。
4. 根据报告中的组件版本、工具风险和模型风险安排修复与复测。

## Web / AI 基础设施扫描目标格式

支持单个 URL、IP 或服务地址，例如：

```text
https://ai.example.com
http://192.168.10.2:8080
192.168.10.2
```

扫描目标按**一行一个表达式**处理；可以直接在输入框中一次性粘贴多行，无需逐行提交。支持的表达式如下：

| 类型 | 可接受示例 | 说明 |
| --- | --- | --- |
| IPv4 CIDR | `192.168.10.0/24` | 展开网段内的 IPv4 地址，保留网络地址和广播地址以保持扫描语义一致。 |
| IPv4 闭区间范围 | `192.168.10.2-192.168.10.10`、`104.147.75.1-104.147.75.10` | 使用标准连字符 `-`，包含起始和结束地址。 |
| IPv4 末尾通配符 | `22.2.10.*`、`22.2.*.*` | 仅允许从某一段开始连续出现在末尾；分别等价于 `/24` 和 `/16`。 |

以下是可直接整体粘贴的多行范围示例：

```text
104.147.75.1-104.147.75.10
104.147.75.12-104.147.75.13
104.147.75.15-104.147.75.30
104.147.75.32-104.147.75.34
104.147.75.37-104.147.75.39
104.147.75.41-104.147.75.102
104.147.75.104-104.147.75.107
```

上述七行会展开为 100 个目标。系统会在正文与附件合并后稳定去重；一个任务最多允许 **65,536** 个展开后的唯一目标。`22.2.*.*` 可以直接使用，但会明显增加扫描耗时、并发连接数量和网络压力，应在明确授权范围内分批执行。

以下格式会被拒绝：

```text
22.*.10.*
104.147.75.1\~104.147.75.10
192.168.10.2:80-192.168.10.10:80
192.168.10.2 192.168.10.3
2001:db8::1
2001:db8::1-2001:db8::2
[2001:db8::1]:443-[2001:db8::2]:443
```

也就是说，本批不支持 IPv6 CIDR、IPv6 范围或 IPv6 通配符、部分八位组通配符、反斜杠/波浪号范围、端口范围和主机名范围。IPv4 范围的两个端点不能携带端口；IPv6 范围即使使用方括号和端口也会被拒绝；范围必须使用标准连字符；不要在同一行用空格拼接多个目标。

AI 基础设施扫描的附件会在服务端作为 UTF-8 纯文本目标清单校验，每个参与解析的附件最大 **1 MiB**。控制台的实时数量只预览正文；正文与已就绪附件合并后的最终语义、容量与授权检查以服务端结果为准。

具体的兼容范围、容量口径和跨层实现约束见[第一批目标输入改造计划](first-batch-target-input-upgrade-plan.md)。

## 使用边界

扫描结果用于发现风险和保留证据，不等于系统“绝对安全”的保证。执行前必须确认目标、网段和附件清单均处于授权范围；优先在测试或隔离环境验证，并结合人工复核、修复和复测闭环处置风险。大范围输入会放大网络影响，应评估扫描窗口、速率和业务承载能力后再执行。
